# かんたんHP作成ツール

テンプレートを選んで、中身を差し替えるだけで自分のホームページが作れるツールです。
できあがったサイトは **HTML1ファイル** として書き出せます。

## 使い方（プロンプトは一切不要です）

`hp-builder/index.html` をブラウザで開くだけ。ビルドもサーバーも不要です。

1. **業種・名前・写真をえらぶ** — 起動時のかんたんモード（下記）。
   テンプレートから選ぶことも、部分ごとに組むこともできます
2. **左でページの構成をいじる** — ブロックをドラッグして並べ替え。
   「＋ ブロックを追加」はサンプル付きの一覧から選びます
   （選択中のブロックの下に入るので、あとからドラッグで動かせます）
3. **右で中身を編集** — テキスト・画像・色。プレビューに即反映されます
4. **公開する** — そのままインターネットに出せます。
   「ファイルに保存」を選べば、HTML1ファイルとして手元にも残せます

- 編集内容はブラウザに自動保存されます（次に開くと続きから）
- プレビューの文字を**ダブルクリック**すると、その場で書き換えられます
  （Esc で取り消し、外をクリックまたは Ctrl/⌘+Enter で確定）
- プレビューの文字や画像を**1回クリック**すると、その要素にアニメーションを付けられます
  （青い枠＝テキスト、紫の枠＝画像・カード。ラベルが出るのでどこを触っているか分かります）
- ヘッダーとフッターは位置が決まっているので、ドラッグの対象外です
- 上のバーの「…」に、たまにしか使わないもの（保存したファイルから続ける／
  中のHTMLを見る／まっさらから作り直す）をしまってあります

## 起動して、いちばん最初の分かれ道

対象は「いまホームページを持っていない人」です。最初に聞くことは1つだけにします。

| | |
| --- | --- |
| **テンプレートから選ぶ** | 出来上がったページを選んで、文字と写真を差し替える |
| **空白からカスタマイズする** | 順に選んで組み上げる |

どちらを選んでも、あとから全部変えられます。前に作ったファイルから続ける道も
ここに置いています（起動直後はこの画面が上部バーを覆っていて、そちらのボタンを
押せないため）。

## 順を追って組む（空白から）

一度に全部を見せません。**いま決めることだけ**を出して、その1つだけを選ばせます。
決めたものは上の帯に積まれていくので、どこまで来たかが分かります。

```
① ビジネス情報   業種・名前（＋連絡先）  ← 飛ばせる
② ヒーローを選ぶ   写真を入れても、入れなくても
③ ブロックを選ぶ   選ぶたびに下へ積まれる
④ ヘッダーとフッター
⑤ できました      → 写真の位置 / 色 / 動き へ
```

### ① は飛ばせます

名前も業種もまだ決まっていない人がいます。**そこで止まってしまうくらいなら、
先に形を見せたほうがいい**ので「あとで入力する」を置いています。

入れておくと、あとから足すブロックにそのまま入ります。

| 入れたもの | 入る先 |
| --- | --- |
| 業種 | ヒーロー・紹介・カードの文章。仮の絵の色と形。配色 |
| 名前 | ヘッダー／フッターのロゴ、ページタイトル、ヒーローの見出し |
| 電話・メール・住所・営業時間 | お問い合わせ、フッター（大きめの型の文章欄） |

**すでに人が書き替えたところは触りません。** 初期値のままのところだけ入れます。

### ② 写真は無くても構いません

写真を1枚も持っていない人が、いちばん最初につまずくのがここです。
空の枠に `IMAGE` と出ているページは作りかけにしか見えず、そこで手が止まります。

そこで、**写真を入れなければ業種に合わせた仮の絵が入ります**（`assets/sample-art.js`）。

本物の写真は持ちません。1枚でもファイルに焼き込むと重くなるうえ、どこかで見た
写真が並ぶことになります。代わりに業種ごとの色と形でその場で描きます。
**1枚900バイト前後**で、拡大しても崩れません。

```js
cafe: { c: ['#efe4d6', '#d6bfa4', '#6b4f3a'], motif: 'circles' },
```

写真を選んだときは、上のブロックから順に入り、足りなくなったところから先が
仮の絵になります。ロゴ枠には入れません（社名の横に店内写真が並んでしまうため）。

**配色も一緒に決まります。** 写真があれば写真の色みから、無ければ業種の色から。
どちらも背景に対して contrast 4.5 を切るなら寄せず、土台の配色のまま使います
（読めない色を出すくらいなら、寄せないほうがましです）。背景が暗いテンプレートでは、
色を暗くするのではなく明るくします。逆方向に動かすと読めなくなります
（`bistro` と `demolition` で実際に起きました）。

### ⑤ 「できました」で終わりにしない

組み上がったところで放り出すと、次に何をすればいいか分かりません。
最後の画面に、**次にできること**を3つだけ置いています。

- 写真の位置と大きさ — プレビューの写真をクリックすると、その場で直せます
- 色を変える — 配色を丸ごと入れ替えるか、1色ずつ
- 動きを付ける — 文字の出かた、スクロールで現れる速さ

押すと画面が閉じて、その欄まで連れて行きます。ここが「組み上げる」から
「整える」への切り替え点です。

なお、この画面では「やめる」を出しません。押すと組み上げたものが全部消えるので、
ここまで来た人が押すボタンではありません。

業種を足したいときは `assets/easy.js` の `INDUSTRIES` に文章を、
`assets/sample-art.js` の `ART` に色と形を、それぞれ1つずつ追加します。

## 名前は英語のロール名、説明は絵で

ブロック・型・動き・形の名前は、**英語のロール名**にしています
（`Hero` / `About` / `Gallery` / `Fade Up` / `Arch`）。

一覧はどれも**実物の絵**が並ぶので、名前で説明する必要がありません。
日本語で説明的な名前を付けると、絵と二重になって、読む量だけが増えます。
言葉での補足が要るものは、カードにマウスを乗せたときだけ出します（`title`）。

分類のチップ（すべて／写真／横に並べる…）は名前ではなく道しるべなので、
日本語のままにしています。

## こまかい調整は、あとから

最初に見せるのは**中身（文字・写真・リンク）だけ**です。速さ・向き・大きさ・
余白・背景色・アンカーのような調整は「こまかい調整」にたたんであります
（`ADV_KEYS`）。数タップで作り終える人の前に、全部を並べません。
たたみの開閉は覚えているので、続けて直したい人の邪魔もしません。

上のバーも6つに減らしました。たまにしか使わないもの
（保存したファイルから続ける／中のHTMLを見る／まっさらから作り直す）は
「…」の中です。「HTMLを書き出す」は**「ファイルに保存」**に言い換えました。

## 部分ごとに選んで組む

まるごと1ページのテンプレートではなく、**1段ずつ選んで積み上げる**やり方もできます。
テンプレート選択の画面から「部分ごとに選んで組む」で入ります。

**型は、置き場所ごとに分けてあります。** ヒーロー・ブロック・フッターは
役目が違うので、同じ一覧に混ぜません。

1. **① ヒーローを選ぶ**（14型）— 中央ぞろえ・写真いっぱい・すりガラス・
   スクロールで写真が縮む・文字の中から写真が広がる、など
2. **② ブロックを選ぶ**（29型）— 選ぶと下に積まれます。必要なだけくり返します
3. **③ フッターを選ぶ**（6型）— 1行／中央ぞろえ／大きめ（ひとこと＋リンク）／
   明るい地／最後にひと押し／ひとことだけ
4. **「これで完成」** — 通常の編集画面に移り、そこから中身を書き替えます

フッターだけは**積むのではなく差し替え**です。1ページに1つしかないので、
選ぶといまのフッターの見た目が変わります（積み上がりの帯にも数えません）。
選ばずに「これで完成」でも構いません。編集画面のフッターからも、
「サンプルを見ながら選ぶ」で選び直せます。

選ぶたびに後ろのプレビューが伸びるので、**出来上がりを見ながら次を決められます**。
上部の帯に、いま積んだものが選んだときの名前で並びます。「1つ戻す」で直前の1段を
取り消し、「やめる」で入る前の状態に戻ります。順番はあとから並べ替えられます。

### 分けかたは「かたち」で

分ける基準は**使い道ではなく、かたち**です。`FAQ` を質問にも料金の内訳にも
使う人がいるので、業種や用途では分けません。分類は
`すべて／写真／横に並べる／縦に並べる／文章・帯／その他` の6つだけです。

名前は英語のロール名（`Accordion` / `Photo L / Text R`）で、見た目は絵が説明します。

```js
{ key: 'features-paren', type: 'features', group: 'カード',
  label: 'Cards ×2 (01)',
  about: '番号を控えめに置く形。落ち着いて見える。',
  props: { style: 'paren', cols: 'c2' } },
```

「型」はブロック種別と初期値の差分でできています（`assets/presets.js`）。
同じ `features` でも、アイコン3列と `( 01 )` 形式は別の型として並びます。
見本は `BLOCKS[type].render()` で実物を描いているので、ここに書いた差分が
そのまま見た目に出ます。型を足したいときは配列に1つ追加するだけです。

### 見本はいつも「広い画面の並び」で描く

見本の中身は生成サイトと同じCSSなので、メディアクエリが効きます。iframe を
画面幅のまま置くと、スマホでは iframe 自体が狭いと判定され、「写真 左 ／ 文章 右」
が縦積みで出てしまいます。名前とかたちが食い違うと、かたちで選べません。

そこで iframe を 1180px の幅で描かせ、丸ごと縮めて枠に収めています
（`galGeom` / `sizeGalFrame` / `galleryCSS`）。縮む分、カードの文字と余白は
1/縮尺 倍にして、画面上の見た目を保っています。

**列数と縮尺は、枠を実際に測ってから決めます。** そのため一覧は
**開いてから組み立てます**。閉じているあいだは枠の幅が 0 で、決め打ちの値に
なってしまい、スマホでもPC用の並びのまま出て右が切れていました（指摘されて直しました）。
画面の向きが変わったときも、開いている一覧だけ組み直します。

一覧の画面は中身が縦に長く、箱ごとスクロールします。そのままだと「閉じる」が
画面の外に出て押せないので、下に貼り付けています。

配色は無彩色寄りのものから始まります。デザインタブでいつでも入れ替えられます。

## ヘッダーのバー（6種）

ヘッダーを選ぶと「バーの型」が出ます。「サンプルを見ながら選ぶ」で、
**いま使っているヘッダー**を型ごとに並べて比べられます。

| 型 | 見え方 |
| --- | --- |
| 線だけ（既定） | 地の色に細い線。固定しているときは半透明になる |
| ベタ塗り | メインカラーで塗り、文字とメニューを白に。ボタンは白抜き |
| すりガラス | 下の中身が透ける。ぼかしが入る |
| 無色（透ける） | 地も線もなし。流れの中には残る |
| ヒーローに重ねる | 流れから外してヒーローの上に置く。写真が画面の上端から始まる |
| 浮かぶ島 | 角の丸い島が浮く。地は擬似要素で敷く |

既定の `line` は、この機能を足す前の見た目そのままです。前に作ったページの
見え方は変わりません。

**重ねる型の文字色は、下を見てから決めます。** すぐ下が写真のヒーロー
（`.hero.cover` / `.hsc.cover` / `.collage`）のときだけ `on-photo` が付いて白字に
なります。地の明るいヒーローに白字を出すと読めないためで、判定は書き出した
HTMLの中の JS が行います（前の兄弟から次を見る CSS は、まだ全部の端末では
当てにできません）。重ねる型では「上に固定」は効かないので、設定欄も出しません。

バーの型のCSSは、スタイルやテンプレートの味付け（`.sty-*` / `.tpl-*`）より
**後ろ**に置いています。同じ強さの指定なので、後ろに書いたほうが勝ちます。
これを前に置くと「無色を選んだのに味付けの線が残る」が起きます（実際に起きました）。

## 写真の形（22種）

写真を持つブロック（ヒーロー・紹介・ギャラリー・カード・フロア・横に流れる・動画）に
「写真の形」が出ます。数が多いので、**「サンプルを見ながら選ぶ」**を押すと
**いま入れている写真**で抜けかたを並べて見比べられます。

基本：`四角のまま／角を大きく丸める／丸／たまご／ひし形／アーチ／木の葉／六角形／斜めに切る`

ひとひねり：`角を四角く欠く／段ちがい／チケット／十字／きらめき`

曲線のある**デザイン寄り**：`4本の柱（上下が交互に丸い）／3連アーチ／下が波／まるいかたまり`

ここまでは、直線と円弧だけで**書き起こしたSVG**です（1つ200〜450バイト）。
拡大しても崩れず、どれだけ足してもページはほとんど重くなりません。

**絵から作った3種**：`丸つなぎ（3×3）／斜めの帯／音の波（縦の棒）`

この3つは、手で書けるSVGでは出せない形（丸どうしが溶けてつながる、帯が
重なる）なので、絵そのものを抜き型として持っています（`assets/shape-masks.js`）。
持ち込まれた画像を、下の「自分で用意した形」と同じ手順で変換して焼き込んだものです。

ページに焼き込むのは**実際に使われている形だけ**です（`usedShapes()` →
`shapeMaskCSS()`）。1つ5〜8KBあるので、使っていない形まで毎回付いてくると
書き出したHTMLが無駄に重くなります。四角に戻せばCSSごと消えます。

そして **「自分で用意した形」**。形の画像を読み込むと、**その形どおりに抜きます**。

- 透明を含む絵（PNGなど）… その透明をそのまま使う
- 透明を含まない絵（白地に色の形など）… ふちから背景をたどって外し、残ったところを形とみなす

どちらも最後は「形のところだけ不透明」の絵になり、`mask-image` に敷きます。
長辺560pxまで縮めてWebPで持つので、抜き型1つは数KBです。
値はブロックの `style` に `--shape` として出るので、書き出したHTMLでも効きます。

こちらは多角形（`clip-path:polygon`）では出せないので、SVGの絵をマスクとして
敷いています。SVGはCSSの中に文字として入れてあるので、外から読み込むものは
増えません（`file://` でもそのまま動きます）。`preserveAspectRatio='none'` と
`mask-size:100% 100%` で枠の形に合わせて伸び縮みします。

**写真そのものは触りません。** 枠の側を `clip-path` と `border-radius` で抜くだけなので、
いつでも四角に戻せますし、書き出したHTMLも軽いままです。抜くのは枠
（`.hero-media` など）で、中の `img` ではありません。枠には下地の色が敷いてあるので、
`img` だけを抜くと下地が形の外に残ります。

背景いっぱいのヒーロー（`cover`）には効かせていません。画面の角が欠けるだけだからです。

## 写真の位置と大きさ

ヒーローは **4つの型すべてで写真を出します**。以前は中央ぞろえ・左ぞろえのとき
画像を入れても何も起きず、入れた本人には壊れて見えていました（指摘されて直しました）。
いまは文章の下に横いっぱいの一枚を置きます。写真いっぱいの型にも枠の目印を付けたので、
押せば選び直せますし、位置と大きさの調整も届きます。

**プレビューの写真をクリック**すると、右の欄が「写真」に変わります。

| | |
| --- | --- |
| 大きさ | 100〜260%。枠いっぱいまで寄せる |
| 横の位置 | 左 ↔ 右（`object-position` の X） |
| 縦の位置 | 上 ↕ 下（`object-position` の Y） |

枠に入りきらない分は切れるので、顔や商品が切れているときはここで寄せます。
「まん中・等倍に戻す」で既定に戻り、そのとき値そのものを捨てるので、
書き出したHTMLに余計な指定は残りません。

写真がすでに入っている枠をクリックしたときは、**写真選択を開きません**。
位置を直したいだけのときに毎回ファイル選択が出てしまうためで、
選び直したいときは欄の中の「写真を選び直す」を押します。
まだ写真の無い枠は、これまでどおり押すとすぐ選択が開きます。

値は枠の `style` に CSS変数（`--ix` / `--iy` / `--iz`）として書き出されます。
編集用の目印（`data-imgprop`）は書き出しで落ちますが、`style` は残るので、
公開したページでもそのまま効きます。一覧の中の写真（ギャラリーやカード）も
1枚ずつ別々に調整できます。

## ページ

はじめは**1枚だけ**です。ページという考えかたは、必要になるまで見せません。
大半の人は1枚で足ります。左下の「＋ ページを追加」を押して2枚目を作ると、
そこではじめてページを選ぶ帯が出ます。

| | |
| --- | --- |
| 名前 | 編集画面と、ほかのページから選ぶときに出る名前 |
| アドレス | そのままファイル名になります（`about` → `about.html`） |
| 中身のはじまり | まっさら／紹介／お品書き／お問い合わせ |

**ヘッダーとフッターは、いまのホームのものをそのまま借ります。** 1枚ずつ
作り直させません。ただしブロックのIDは別なので、片方を直しても
もう片方は動きません（共通のヘッダーが要るという声が出たら、そのとき考えます）。

配色・デザインの型・動きは**サイト全体で共通**です。ページごとに変えられると
バラバラのサイトになり、直す場所も増えます。

ホームの名前とアドレスだけは変えられません。`index.html` はどの置き場所でも
「入口」として扱われる決まりで、ここを動かすとサイトが開かなくなります。

### 書き出しは、1枚ならこれまでどおり

| ページ数 | 書き出し |
| --- | --- |
| 1枚 | `index.html` が1つ（これまでと同じ） |
| 2枚以上 | ページごとに1ファイル。ZIPにまとめて1回で渡します |

ブラウザに複数のファイルを続けて保存させようとすると、2つ目以降が
「まとめてダウンロード」の確認で止まる端末が多いためです。ZIPなら1回で済み、
Netlify などの「ここにドロップ」もZIPをそのまま受けます。

圧縮はしません（stored）。中身は写真がデータURLで入っていて、そのほとんどは
既に圧縮済みの絵なので、縮めても効きが薄いわりに実装が重くなります。
`assets/zip.js` が仕様どおりのバイト列を組みます（外から読み込むものは無し）。

**組み立て情報（控え）は `index.html` にだけ入れます。** 全ページに入れると、
写真をページの数だけ持つことになって、まとめて重くなります。2枚目以降には
目印だけ置いて、間違って読み込まれたときに「index.html を読み込んでください」
と言えるようにしています。

### タブ名と説明

ページごとに `<title>` と説明を持てます。空なら **`ページ名｜サイト名`** に
なるので、ふつうは何も入れなくて構いません。ホームはサイト名がそのまま出ます。

## ボタンやメニューの行き先

URLを手で書かせません。ホームページを持っていない人にとって `#contact` も
`tel:03-…` も知らない書きかたで、**打ち間違えても間違えたことに気づけません**
（押しても何も起きないだけです）。

何をしたいかを選ぶと、その先は選択肢か、ふつうの入力になります。

| 選ぶもの | 出る欄 |
| --- | --- |
| ページへ | 作ったページの一覧 |
| このページの中へ | アンカーIDを付けたブロックの一覧 |
| 電話をかける | 電話番号（`tel:` は自動で付きます） |
| メールを送る | メールアドレス（`mailto:` は自動） |
| 外のサイトへ | URL |
| リンクなし | — |

**ページへのリンクは、住所ではなくページIDで持ちます。** あとでアドレスを
変えてもリンクは切れません。書き出すときに実際のアドレスへ直します。
指していたページを消したときは、押しても飛ばないだけで、ページは壊れません
（消す前に「このページへのリンクが◯か所あります」と出ます）。

行き先は「こまかい調整」に入れていません。どこへ飛ぶかはボタンの文字と
同じくらい大事な中身で、ページを足せるようになってからは
「打つもの」ではなく「選ぶもの」になったからです。

### プレビューの中でも本当のアドレスが出ます

ただしプレビューは1枚のHTMLなので、押しても隣のファイルへは飛べません。
代わりに `data-gopage` を付けておき、押されたら**編集中のページを切り替えます**。
押した人が期待するのは「そのページが出ること」なので、そちらに合わせています。
書き出すときにこの目印は落ちます。

## 絵で並べる（設備・条件）

「Wi-Fiあり」「駐車場あり」「全面禁煙」のような**設備や条件**を、絵と短い言葉で
並べるブロックです。文章で書くと読まれませんが、絵なら一目で分かります。

| | |
| --- | --- |
| 横に並べる数 | 2列／3列／4列（スマホではどれも2列） |
| 絵の大きさ | 小さめ／ふつう／大きめ |
| 中身 | 「絵」と「言葉」の組を、好きなだけ足せる |

言葉は改行がそのまま出ます（`大画面の` ⏎ `スクリーン`）。長い言葉を1行に
詰めるより、意味の切れ目で折ったほうが読みやすいためです。

### 絵は絵文字ではなく、線で描いたSVGです（110種）

絵文字は端末ごとに形も色も変わり、同じページが人によって別物に見えます。
そこで 24×24 のパスとして自前で持っています（`assets/icons.js`）。

線は `currentColor` なので、**文字の色にそのまま従います**。配色を変えると
絵の色も一緒に変わり、色を指定して回る必要がありません。太さは `1.6` で
そろえてあります。1つ100〜500バイトなので、何種類増やしてもページは重くなりません。

```js
key: { label: '画面に出す名前', g: '設備', d: `<path d="…"/><circle …/>` },
```

置いてあります（名前が思い浮かんでいる人にはそのほうが速い）。

### 形は「読めるか」で決めています

絵は描いてから**必ず一覧に並べて目で見て**、読めないものは描き直しています。
実際に描き直したもの：

- **禁煙** — 線だけのたばこが矢印にしか見えず、輪郭のある形に
- **土足** — 4つの点にしか見えず、靴の側面図に
- **トイレ** — 便器の側面図はワイングラスに見えるので、男女のピクトグラムに
- **電車とバス** — 同じ角丸四角で見分けが付かず、電車は窓を1枚に、バスは車輪を外へ
- **エレベーター** — 山形2つが写真アイコンに見えるので、棒の付いた上下の矢印に
- **本** — ただの四角だったので、開いた本に

読めるかどうかは描いた本人には分からないので、判断はいつも並べた絵を見てからです。

## 写真が流れ続ける（導入実績など）

写真が右から左へ流れ続けるブロックです。導入実績・取引先・受賞歴のように
**数が多くて縦に積むと長くなるもの**に向きます。

| | |
| --- | --- |
| 見せ方 | 写真だけ／**カード（写真の下に見出しと説明）** |
| 大きさ | 小さめ／ふつう／大きめ |
| 写真の形（縦横比） | 4:3／正方形／16:9／縦長 |
| 速さ | 10〜90秒で1周 |
| 向き | 右から左へ／左から右へ |

**写真の形（22種）も土台も、ほかの写真と同じように効きます。** 枠は `.strp-pic` で、
形・土台・位置調整の対象にまとめて入れてあります。

流れる文字と同じで、**同じ並びを2組**出して片方が抜けた瞬間にもう片方が続く形です
（`translate3d(-100%)` で1組ぶん動かす）。2組目は同じ絵の続きなので、
読み上げには渡しません（`aria-hidden`）。両端はうすく消して、切れ目ではなく
「続いている」ように見せています。

- **マウスを乗せる（タップ）と止まります** — 読みたい人が止められます
- 「動きを減らす」設定の端末では、流れずに止まって並びます

## 動画を置く

ヒーローにもブロックにも動画を入れられます。**動画そのものは持ちません。**
1ファイルに収める作りなので、数十MBの動画を抱えると保存も公開もできなくなります。
URLを受け取って、置き場所だけを作ります。

| 入れるもの | どうなるか |
| --- | --- |
| YouTube のURL（`watch` / `youtu.be` / `shorts`） | 埋め込み再生（`youtube-nocookie.com`） |
| Vimeo のURL | 埋め込み再生 |
| `.mp4` `.webm` などのURL | 自前で再生（自動再生・くり返しも選べる） |

- **ブロック**：「動画を1つ置く」。画面の形は 16:9／4:3／正方形／**縦長（スマホ動画）**から選べます
- **ヒーロー**：写真いっぱいの型のとき「背景の動画URL」に `.mp4` を入れると、写真のかわりに流れます（音は出ません）

動画の枠は写真の枠と同じ扱いなので、**写真の形も土台もそのまま効きます**。
自動再生は「音が出ない・その場で再生する」が揃わないと端末側に止められるので、
両方まとめて付けています。

## 文字を絵で塗る（文字のくり抜き）

**プレビューの見出しをクリック**すると、右の欄に「文字の塗り」が出ます。
背景を文字の形に切り抜いて見せるので、**文字は文字のまま**です。
読み上げにも検索にも残りますし、あとから書き換えられます。

| | |
| --- | --- |
| グラデーション（0バイト） | 金／炎／銀・メタル／夜／虹／メイン色→アクセント色 |
| 絵（使ったときだけ入る） | 炎の写真／黒い多面体／白い多面体 |
| 持ち込み | 自分の画像で塗る |

グラデーションはCSSだけで作れるので、いくつ足してもページは重くなりません。
絵のほうは1つ3〜19KBあるので、**実際に使われている絵だけ**を焼き込みます
（`usedFills()` → `textFillCSS()`）。「塗らない」に戻せばCSSごと消えます。
持ち込んだ画像は長辺900pxまで縮めてWebPで持ちます。

`background-clip:text` が効かない環境では、文字が消えるのではなく
**元の文字色で出ます**（`@supports not` で戻しています）。

## 写真の土台

写真の下に色の面を敷き、写真をひと回り小さく載せられます。

| | |
| --- | --- |
| 土台の色 | 濃い地／メインカラー／アクセント／薄いグレー／白 |
| 見せ方 | 写真のまわりに均等／右下・左下・右上・左上にずらす |

面のかたちは**「写真の形」と同じもの**を使うので、22種そのまま土台に使えます
（土台がアーチなら、写真もアーチの内側に収まります）。

要素は増やしていません。枠の余白と地の色だけで作っていて、写真は枠の内側
いっぱいなので、余白のぶんが土台として見えます。

## ボタンの型

見た目・大きさ・矢印を、それぞれ別に選べます。

- 見た目：`塗り（メイン）／塗り（アクセント）／枠線だけ／丸（ピル）／角なし／濃い地／白抜き／下線だけ／ずらした影`
- 大きさ：`ふつう／大きい／小さい／横いっぱい`
- 矢印：付けると、押したときに矢印だけ先に動きます

ボタンの型のCSSは、スタイルやテンプレートの味付け（`.sty-*` / `.tpl-*`）より
**後ろ**に置いています。前に置くと「下線だけ」を選んだのに角丸が残ります（実際に起きました）。

## 背景をぬく

写真を1枚入れると「背景をぬく」が出ます。**端末の中だけで処理し、写真はどこにも送りません。**

やり方は「**ふちから**、背景に近い色をたどって消す」です。全体から背景色に近い画素を
消すやり方だと、被写体の中の白（皿・服・歯）まで抜けてしまいます。ふちからつながって
いる画素だけを消せば、それが起きません。

- 効くもの … 白い壁・単色の背景、商品写真、ロゴ
- 効かないもの … 人物、雑多な背景（きれいに抜くには学習済みモデルが要ります）
- ぬく範囲はスライダーで調整でき、「背景と判断したところ ○%」が目安に出ます
- 入れたあとでも「取り消し」で元の写真に戻せます

書き出しは **WebP（透過つき）**です。PNG は写真だと非常に重く、512pxの写真でも 255KB に
なりました（1ページ3MBの上限に当たります）。同じ写真が WebP なら 16KB です。
WebP を作れない環境では PNG に落ち、それでも 700KB を超えるときは縦横を縮めます。

## 編集画面のCSSは、ページの見た目を変えない

編集画面では、画像の枠に目印を出すために `[data-imgprop]` へスタイルを当てています。
ここで `position:relative` を普通に指定すると、**自分で配置を決めているブロック**
（回るカード `.car-it`、円で切り替わる面 `.clip-side`、背景いっぱいの写真 `.hero-bg`）の
`position:absolute` を上書きして、編集画面だけ並びが崩れます（実際に崩れていました）。

いまは `:where([data-imgprop])` で当てています。`:where()` は強さが 0 なので、
ブロック側が自分で決めた配置が必ず勝ち、何も決めていない枠にだけ `relative` が入ります。

この観点は機械で見ています（`verify-editcss.js` 相当）。**編集画面での姿と、
書き出したページでの姿**を突き合わせ、ページ側が自分で決めている配置を
編集画面が変えていないかを確かめます。回るカードについては「輪の上に並んでいるか
（縦のばらつきが小さいか）」も見ます。

### 決めるのは4色だけ。薄いところは自動でそろえる

色の欄が8つ並んでいると、手が止まります。「メインカラー」「文字色」は分かっても、
**「薄いエリア」「うすい文字」「線」「濃いエリア」が何に効くのかは、
実際に使われる場所を知らないと決められません。**

| | |
| --- | --- |
| **決める色** | メインカラー ／ アクセント ／ 背景 ／ 文字 |
| **ついてくる色** | 薄いエリア ／ うすい文字 ／ 線 ／ 濃いエリア |

決める色を動かすと、ついてくる4色もその場で作り直されます（`assets/tone.js`）。
作りかたは「地から少しずらす」だけなので、配色を変えても崩れません。

```
薄いエリア   明るい地 → 文字色へ 5%（地が白でなければ白へ寄せる）
線         明るい地 → 文字色へ 16%
           暗い地   → どちらも白へ（5.5% / 14.5%）。文字色ではなく白を使う
うすい文字   地に寄せていって、contrast 4.5 を切る手前で止める
濃いエリア   明るい地 → 文字色そのもの ／ 暗い地 → 地をさらに 28% 暗く
```

**色みは主役の色から少しだけ借ります。** ただし借りる量は、主役の色が鮮やかなほど
減らします。鮮やかな色をそのまま混ぜると、薄いエリアまで色付いて見えるためです。

**うすい文字だけは、混ぜ具合では決めません。** 地に寄せすぎると読めなくなるので、
`contrast 4.5` を切る手前で止めます。読めない灰色は、薄いのではなく壊れています。

作った色は**画面に出したままにします**（名前・どこに出るか・色の値）。
黙って決められるのが、いちばん分かりにくいからです。
自分で決めたい人は「薄いところは自動でそろえる」を外すと、4つの欄が出ます。

**14種のテンプレートすべてで検算しています** — 自動でそろえた場合でも、うすい文字は
4.50 以上、薄いエリアの上に置く文字は 10.16 以上。手で決めてある元の色との差も、
ほとんどが見て分からない範囲（RGB距離 30 以下）に収まります。

前に作ったページを読み込んだときは、**そのときの色をそのまま残します**。
読み込んだだけで塗り替えず、決める色を動かした時点から追従します。

### 文字色の自動調整

メインカラーの明るさを測って、その上に置く文字色（`--c-on-primary`）を白か黒に自動で決めています。
黄色などの明るい色をメインにしても、帯やボタンの文字が読めなくなりません。

## 使えるブロック

ヘッダー / ヒーロー / 特徴・サービス / 絵で並べる（設備・条件） /
紹介（画像＋文章） / ギャラリー /
コラージュ（縦書き＋斜め写真） / お品書き（価格表） / フロアガイド /
お知らせ・イベント / 流れる文字 / 料金プラン / よくある質問 / CTA帯 /
お問い合わせ / 自由テキスト / フッター

### お知らせ・イベント

日付・カテゴリ・見出しを1行に並べた一覧です。行にポインタを乗せると少し右にずれます。
「もっと見る」ボタンは、文字を空にすると消えます。
狭い画面では見出しだけが次の行に落ちます。

### フロアガイド

階ごとに「階数・名前・説明・画像」を並べます。商業施設・ビル・複合施設向けです。
偶数番目は左右が入れ替わり、狭い画面では縦積みになります。

### 流れる文字（マーキー）

同じ言葉が横に流れ続ける帯です。区切りのしるしや、お問い合わせの手前に置きます。

- 速さ（1周8〜60秒）・向き（左／右）・文字の大きさを変えられます
- **中を抜いた文字**にすると、線だけになるぶん大きく置いてもうるさくなりません
- リンク先を入れると帯ごとリンクになります。ポインタを乗せると止まります

途切れずに流すため、同じ並びを2組ならべて1組ぶんだけ動かしています。

### 縦の罫線（デザインタブ）

左・中央・右に細い線を通すと、全体が図面のように締まります。
画面に固定しているのでスクロールしても動きません（スマホでは左右の2本だけ）。

### お品書き（価格表）について

カフェ・飲食店・サロン向けの、品名と価格を並べるブロックです。
カテゴリ（COFFEE / FOOD など）ごとにまとめ、品名と価格を点線でつなぎます。

品目は1行に1品、**「品名 | よみ | 価格」**のように縦棒で区切って書きます。

```
Drip Coffee | ドリップコーヒー | 550
Café Latte | カフェラテ | 600
```

縦棒が足りない書き方（`ドリップコーヒー | 550` など）でも壊れません。
最後のひとつを価格、先頭を品名として扱います。

品名が長くて折り返しても、価格は右端にそろったままです。
カテゴリの右肩には「HOT / ICED」「サラダ・スープ付」のような注記を置けます。

**スクロールに連動する特別なブロック（9種）**

| ブロック | 内容 |
|---|---|
| 3D製品ビュー | スクロールで立体が360°回転。画像不要、形と色だけで作られます |
| 分解図が組み上がる | バラバラの層が合体。各層に画像を入れられます |
| 横に流れるギャラリー | 縦にスクロールするとカードが横に流れます |
| 積み重なるカード | カードが重なりながら積み上がります |
| タイムライン | 線が伸びて、通過した項目が点灯します |
| 円形マスクで切り替え | 円が開いて下の世界に入れ替わります |
| 3Dカルーセル | 円環に並んだカードが回ります。ドラッグでも回せます |
| 数字カウンター | 桁ごとに数字が縦に回って止まります（下記） |
| 折れ線・棒グラフ | 線の下に色が敷かれ、うっすらとマス目が入ります（下記） |
| 全画面メッセージ | 画面いっぱいに1つの言葉。色を変えると空気が変わります |
| スライドページ | スクロール1回で1枚めくる全画面スライド（下記） |

## グラフと数字

線1本と枠だけの図は、**作りかけの下書きに見えます。** 面・目盛り・点を敷いて、
図として成立させています。

### 折れ線・棒グラフ

| | |
| --- | --- |
| 見せかた | 折れ線 ／ 棒（重ねる形は持ちません） |
| 線の下 | 同じ色の薄い膜。マス目はその上に出ます |
| マス目 | 0/25/50/75/100 に細い線。数えるためではなく、高さを比べるための下敷き |
| 線 | 太さ 3.5、端は丸。既定でなめらかな曲線（Catmull-Rom を3次ベジェに） |
| 点 | 帯の地の色でふちを抜くので、線に重なっても読めます |
| 数値 | 目盛りごとに任意で入れられます。点の真上に置かれます |

**棒と折れ線を重ねる形は持ちません。** 重ねると線と棒で色が2つ要り、図が濁ります。
前の版でその指定になっていたページは、折れ線として出ます。

### 図の色は1色だけ

線・棒・膜・点を、すべて同じ色にしています。**2色を混ぜたグラデーションは、
色が濁って安っぽく見えます。** 濃さの差は、その帯の地の色へどれだけ寄せるかで作ります。

```
棒   濃い = その色そのまま      → 薄い = 地へ 70% 寄せた同じ色
膜   薄い = 地へ 74% 寄せた色   → 地の色そのもの（消える）
```

**透かしているわけではありません。** 透明度で薄くすると、下にあるマス目や
地の模様が透けて濁ります。地の色へ寄せた不透明な色を置いています。

`color-mix` を読めない端末のために、まず不透明度で薄くしたものを置き、
読める端末だけ `@supports` で上書きします。読めないまま黒く塗られると図が潰れます。

**棒は下から立ち上がり、線は引かれ、そのあと膜がにじみます。** 棒は塗りなので
「線を引く動き」（`stroke-dasharray`）が効きません。下端を軸にした `scaleY` で伸ばします。

**折れ線だけのときは、点を端から端まで広げます。** 棒の真ん中に合わせたままだと、
膜の右端が縦線になって切りっぱなしに見えるためです。ラベルと数値は目盛りと同じ
`x` で置くので、どちらの並べかたでもずれません。

**濃い地の上では、主役の色が沈みます。** そこで図の色を変数（`--c-chart`）にして、
`bg-dark` / `bg-primary` の上ではその帯の文字色に差し替えます。グラデーションの
色止めも同じ変数を見るので、濃い地でも面のある図のままです。

**動きを減らす設定では、最初から出来上がった形で置きます。** 伸びる前の状態は
「高さ0・点が消えている」なので、そのままだと図が現れません。

グラデーションの名前は中身から作ります（`hashId`）。同じページに図を2つ置いても
混ざらず、同じ中身なら書き出すたびに同じHTMLになります。

### 円グラフ

細い輪はグラフに見えないので、**直径の20%**の太さにしました（前は9%）。
下地の輪を敷き、同じ色の濃い→薄いグラデーションで満ちていきます。

### 数字

数字は「読ませる」ものではなく「効かせる」ものです。小さいと、ただの注記に見えて
何も残りません。**見出しと同じくらいの大きさ**にしました。

| | 前 | いま |
| --- | --- | --- |
| カウンター | 30〜78px | 44〜110px |
| スライドの数字 | 34〜89px | 46〜120px |

等幅フォント（Menlo）をやめて見出しのフォントを使い、桁がそろうよう
`font-variant-numeric: tabular-nums` を効かせています。

**桁の窓の高さ・1桁ぶんの送り・行の高さは、3つとも `1.1em` でそろえます。**
JSが `translateY(-数字×1.1em)` で送るので、どれかがずれると上下の桁が窓から
はみ出して見えます（行間を詰めたときに実際に起きました）。

### スライドページについて

「1スクロール＝1枚だけ進む」「表示のたびに図と数字を最初から再生」を満たすブロックです。
左に動く図（棒グラフが伸びる / 線が描かれる / 円が満ちる）、右に番号・見出し・
リード文・箇条書き・大きな数字を置きます。右端に固定のドットナビが出ます。

**ページ全体を乗っ取る作りにはしていません。** 元の仕様は `html,body{overflow:hidden}` で
ページ全体をスライドにする前提でしたが、それだとヘッダーも他のブロックも置けなくなるため、
固定セクションの中でめくる方式にしています。結果として「最初と最後ではスクロールが
前後のセクションに渡る」は自動的に満たされ、慣性スクロールで突き抜けるガードも不要です。

スマホ（768px以下）では縦積みの通常スクロールに切り替わり、
各スライドが画面に入るたびにアニメーションが再生されます。

「＋ ブロックを追加」を押すと、**実物のサンプルが並んだ一覧**が開きます。
カテゴリ（基本 / スクロール連動 / 3D / 数字・図解 / 演出）で絞り込めます。
サンプルは生成サイトと同じCSSでその場に描いているので、見たままが入ります。

各ブロックには「背景色」と「アンカーID」があります。
アンカーIDに `about` と入れておけば、メニューのリンク先に `#about` と書くだけで
そこまでスクロールするようになります。

## 画像について

入れかたは3通りです。

1. **プレビューの画像枠をタップ / クリック** — 端末の画像選択が開きます
   （スマホならカメラロール）。いちばん手数が少ない方法です
2. **画像ファイルを枠にドラッグ&ドロップ**（パソコン）— 枠が紫の点線に変わったら放します
3. 右パネルの「画像を選ぶ」ボタン、または画像URLを直接入力

取り込むときに**長辺1600pxまで縮小**し、JPEGに変換します。スマホの写真は
そのままだと数MBあり、ブラウザの保存上限をすぐ超えてしまうためです。
400KB以下かつ1600px以下の画像は、変換せずそのまま使います。
SVGとGIFは描き直すと壊れる（ベクタ / アニメーション）ので変換しません。

写真の向き（EXIF）は `createImageBitmap` の `imageOrientation` で補正しています。

- 画像はデータURLとしてHTMLに直接埋め込まれます。1ファイルで完結する代わりに、
  枚数が増えるとファイルも重くなります
- 自動保存の上限（おおむね5MB）を超えると保存だけができなくなります。
  編集と書き出しは続けられるので、その場合はHTMLを書き出してください
- 未設定の画像枠には `IMAGE` のプレースホルダが出ます

## 公開する

対象の利用者にとって、ここが最後でいちばん高い壁です。
「HTMLを書き出しました」で放り出すと、その先に進めません。

「公開する」を押すと、3画面で公開先まで連れて行きます。

1. **公開先を選ぶ** — Netlify Drop（いちばん簡単）／ GitHub Pages ／ 持っているサーバー
2. **手順を1手ずつ** — 押すボタンをその場に置きます（書き出す・公開先を開く）
3. **アドレスを控える** — 次からは公開ずみの画面から始まり、更新のしかたが出ます

控えたアドレスは `<link rel="canonical">` と `og:url` として書き出しに入ります。

### そのまま公開する（Firebase）

`assets/publish-config.js` に公開先を設定すると、選択肢の先頭に
**「このまま公開する」** が出ます。押すだけで公開まで終わり、
アドレスがその場で出ます。登録もファイルの置き場所も要りません。

仕組みと出し方は `firebase/README.md` にまとめてあります。要点だけ:

- 持ち主の証明は**合言葉**だけ。ログインを求めません
- 合言葉は**手元にダウンロードするHTMLにだけ**入れ、公開する版からは外します
- 編集ツールは Firebase SDK を読み込みません。公開のときに `fetch` を1回するだけです
- 設定を空にすると、この道は消えて「自分で置く」だけになります

## お問い合わせフォーム

**「見た目だけのフォーム」は、いちばんたちの悪い作りかたになります。**
押した人は送ったつもりで待ち、受け取る側は何も来ないことに気づきません。
そこで既定を「このツールで受け取る」にしています。

| 届け先 | 何が起きるか |
| --- | --- |
| **このツールで受け取る**（既定） | 預かって、編集画面の「届いたお問い合わせ」で読めます |
| ほかのサービスに送る | Googleフォーム等のURLへ、ふつうの `<form>` として送ります |
| 見た目だけ | 何も付けません |

受け口は公開のときと同じ Cloud Function です（`/api/form`）。
**メールは送りません。** 送るには外の配信業者と、その鍵の管理が要ります。
代わりに預かって、読みに行ける場所を作りました。

読むときの持ち主の証明は**公開と同じ合言葉**です。合言葉は手元のデータの中に
あるので、入力は求めません。覚えるものは増えません。

### 送れないときに、黙って消さない

- 送っている間はボタンを止めて「送信中…」に変えます
- 送れたら欄を空にして、お礼の言葉を出します
- **送れなかったときは欄をそのまま残します**。打ち直させません
- 断られた理由（送信が続いています、など）はそのまま出します
- 公開前など届け先が決まっていないフォームは、**押しても送信せず**
  「ただいま受付を準備中です」と出します。そのままだとページが読み直されて、
  打った内容が黙って消えます

### 機械よけ

人には見えないが自動で埋める道具には見える欄（honeypot）を1つ置いています。
ここが埋まっていたら人ではないので、受け口で**静かに捨てます**。
はっきり断ると、避けかたを教えることになります。

`display:none` にはしません。見つけて避けられるので、画面の外へ出しています。

そのほか、受け口の側で:

- 同じ回線から1日30通まで
- 1サイトに貯めるのは500通まで（古いものから捨てる）
- 1つの欄は4000文字まで
- メールアドレスの形が違えば断る

### まだできないこと

既存サイトのURLを読み込んで作り直す機能は作れません
（ブラウザからは他所のサイトを読めません）。

## 保存と持ち運び

編集中の内容はブラウザに自動保存されますが、**それだけでは端末を替えると消えます**。
そこで、**書き出したHTML自身が控えを兼ねる**ようにしています。

- 「HTMLを書き出す」で出したファイルを、「HTMLを開く」から読み込めば続きから編集できます
- パソコンなら、画面にファイルを放り込んでも開きます
- 起動直後の画面にも「作ったHTMLを開く」を置いています。
  この画面が上部バーを覆っていて、そちらのボタンを押せないためです

スマホで書き出したファイルをパソコンに送れば、そのまま続きを編集できます。
サーバーもログインも要りません。利用者が管理するファイルは1枚のままです。

### 写真を二重に持たない

組み立て情報は `<script type="application/json" id="hp-builder-data">` に入ります。
ただし写真をそのまま入れると、本文とあわせて倍の重さになります。

そこで本文に出てくるデータURLを出てきた順に数えて、控えの側は
`@@hpimg:0` のような**番号だけ**を持ちます。読み込むときに番号から戻します。
写真4枚（317KB）のページで、書き出しは407KBでした（二重なら700KB超）。

数える範囲は本文だけに揃えています。生成サイトのCSSに
`data:image/svg+xml` が1つ入っているため、文書ぜんぶを数えると番号が1つずれます。

本文に出てこない写真（表示されない項目に入っているものなど）は参照しようがないので、
控えの側にそのまま持たせます。

```
├── assets/
│   ├── builder.css         編集画面のUI
```

## 公開する

リポジトリ直下の `docs/` に、そのまま置けば動く一式が入ります。
ビルドもサーバー処理も要りません。

```
node build-site.js     # docs/ を組み立てる
node verify-site.js    # 公開後と同じHTTP越しに確認（要 playwright）
```

できあがり：

| パス | 中身 |
| --- | --- |
| `docs/index.html` | サービスLP（入口） |
| `docs/app/index.html` | 編集ツール本体（1ファイル） |
| `docs/demo/` | 作例4種と、その入口ページ |

**GitHub Pages で出す** — Settings → Pages → Source を「Deploy from a branch」、
ブランチを選び、フォルダに **`/docs`** を指定。数分で
`https://<ユーザー名>.github.io/<リポジトリ名>/` に出ます。

出力先がリポジトリ直下なのはこのためです。ここで選べるフォルダは
「/（リポジトリ直下）」と「/docs」の2つだけで、`hp-builder/docs` のような
深い場所は選択肢に出てきません。

**それ以外** — Netlify・Vercel・レンタルサーバーのいずれも、`docs/` の中身を
そのままアップロードするだけです。ビルドコマンドの設定は要りません。

`docs/.nojekyll` は、GitHub Pages が既定で通す Jekyll を止めるための空ファイルです
（`_` で始まる名前などが消されるのを防ぎます）。

## 増やしたいとき

**ブロックを増やす** — `assets/blocks.js` の `BLOCKS` に1つ足します。
`fields` を書けば編集フォームは自動で生成されます（`text` / `textarea` / `select` /
`toggle` / `color` / `range` / `image` / `list`）。最後に `ADDABLE` へキーを追加。

```js
news: {
  label: 'お知らせ', icon: '!',
  fields: [ FIELD.title, { key:'items', type:'list', item:[ ... ] }, FIELD.bg, FIELD.anchor ],
  defaults: { title:'お知らせ', items:[], bg:'', anchor:'news' },
  render: (p) => sec('news', p, `...HTML...`),
}
```

**テンプレートを増やす** — `assets/templates.js` の `TEMPLATES` に、配色（`theme`）と
初期ブロック（`blocks`）を書きます。`blocks` には各ブロックの `defaults` からの
差分だけ書けばOKです。

## 制約

- 1ページ構成のサイト向けです（複数ページはブロックを組み替えて別々に書き出してください）
- お問い合わせフォームは見た目だけです。実際に送信するには、送信先URL欄に
  Googleフォームなど外部サービスのURLを設定してください
- 保存先はブラウザのlocalStorageなので、別のPC・別のブラウザには引き継がれません

## 取り消し / やり直し

左上の `↶` `↷`、または **Ctrl/⌘+Z**（やり直しは **Ctrl/⌘+Shift+Z**）。
プレビューの中にフォーカスがあるときも効きます。

- 並べ替え・追加・削除・文字の書き換え・アニメの設定・配色まで、すべて戻せます
- 文字入力は連続した打鍵を1回分にまとめるので、1回の取り消しでまとめて戻ります
- 入力欄や直接編集の最中は、ブラウザ本来の文字取り消しを優先します
- 取り消したあとに別の操作をすると、それ以降のやり直しは消えます（通常の編集ソフトと同じ）

履歴は state の丸ごとコピーを積む方式です。画像をデータURLで持てるため、
40件かつ合計12MBの上限を設け、超えた分は古いものから捨てています。

## スマホでの編集

820px以下では、3カラムから「プレビュー1枚＋下から出るシート」に切り替わります。

- 下部ナビ: **構成 / 編集 / デザイン / 追加 / 書き出す**
- プレビューの要素をタップすると、編集シートが自動で開きます
- 文字の編集は、要素をタップ →「✎ 文字を編集」（プレビューのダブルタップでも可）。
  キーボードで隠れないよう、編集を始めるとシートは閉じます
- 並べ替えは `⠿` を指で掴んで上下に動かします。一覧の端まで運ぶと自動でスクロールします
- タップ環境ではホバーが無いため、↑↓・複製・削除のボタンは常に表示されます

指でのドラッグは HTML5 のドラッグ&ドロップが効かないため、Pointer Events で別に実装しています。
移動と終了は document 側で受けており、`setPointerCapture` が使えない環境でも最後まで追えます。

### 画面の四隅の「触れない場所」

iPhone では上に時計、下にホームバーが重なります。**ここを避けないと、上のバーの
ボタンが時計の下に潜って切れて見えます**（実機で起きました）。

```css
:root{
  --sat: env(safe-area-inset-top, 0px);
  --sab: env(safe-area-inset-bottom, 0px);
}
```

| 場所 | どうしているか |
| --- | --- |
| 上のバー | 高さを `48px + --sat` にし、上に `--sat` の余白。**地の色は画面の上まで届かせます**（帯の下だけ空けると段差になります） |
| 下のナビ | 高さを `60px + --sab` にし、下に `--sab` の余白 |
| 下から出るシート | ナビの上（`60px + --sab`）に付きます |
| 画面いっぱいの窓 | 上下に帯のぶんの余白。高さは `100dvh − --sat − --sab − 24px` まで |

`env()` は `viewport-fit=cover` を書かないと 0 のままなので、viewport にも足しています。
そのうえで `env()` を直に書かず**変数を1度通している**のは、検査から値を差し替えて
「時計がある端末」を作れるようにするためです（Playwright は `env()` を作れません）。

高さは `100dvh`。`100vh` のままだと、スマホで上下のバーが引っ込んだときの高さで
計算され、下のナビが画面の外に出ます。読めない端末のために `100vh` も残しています。

パソコンでは `env()` がすべて 0 なので、見た目は今までどおりです。

## 動き（アニメーション）

デザインタブの「動き」で、サイト全体の見た目に動きを付けられます。

- **見出しの文字アニメ** — 12種類（なし / フェードアップ / 行マスクせり上げ / ぼかし解除 /
  3Dフリップ / 回転して落ちる / 弾む / 左右交互スライド / 散らばりから集合 / ネオン点灯 /
  グラデーションで塗る / スクランブル / タイプライター）。すべての見出しに適用されます
- **アニメの長さ・1文字ごとのずらし・イージング** — 速さと質感の調整
- **ブロックをスクロールで出現させる** — 各セクションが下からふわっと現れます

### 寸法は画面幅に比例させています

**1440pxを基準に比例、2000pxで頭打ち**という作り方にしています。
参考にした制作会社のサイトはどれもこの方式でした。

```
min(100vw / 1440 * 56, 2000/1440 * 56px)   ← 見出し56pxの場合
```

これをやらないと、**広い画面でデザインが伸びるのをやめます。**
以前は1920pxでも1440pxとまったく同じ寸法で、余白だけが左右に余っていました。

| | 1024px | 1440px | 1920px |
|---|---|---|---|
| 見出し | 39.8px | 56px | 74.7px |
| 節見出し | 22px | 30px | 40px |
| 本文 | 15px | 18px | 24px |
| 節の上下余白 | 93.9px | 132px | 176px |

`clamp()` の下限はそのまま残してあるので、狭い画面で文字が小さくなりすぎることはありません
（390 / 1024 / 1920 / 2560px で、11px未満の本文が0件・横はみ出し0件を確認）。

**1440pxでの見た目は1pxも変えていません。** いまのデザインを保ったまま、
比例するようにだけ直しました（43箇所を機械的に変換）。

### 慣性スクロール

デザインタブの「動き」から入れられます（初期状態は入り）。
ホイールを止めたあとも少し滑ってから止まります。
高い制作費のサイトの「手触り」は、装飾よりここで決まります。

**中身をまるごとずらす方式は使っていません。** よくある実装は `wrapper` を
`transform` でずらしますが、それだと `position:sticky` が効かなくなります。
このツールは貼り付くブロック（横に流れるギャラリー、スクロール連動ヒーロー、
積み重なるカード）を多く持つので、**ページ本来のスクロール位置そのものを
なめらかに動かす**方式にしました。sticky も IntersectionObserver もそのまま動きます。

- マウスのある環境だけで働きます。指の操作では切れます
- 「動きを減らす」設定では切れます
- 中でスクロールできる箱（コード表示など）の上では、そちらに任せます
- キーボードやアンカーで飛んだときは、目標位置を合わせ直します

書き出したHTMLでもそのまま働きます。

### 出現のしかた

ブロックごと一度に出すと「表示された」で終わります。
見出し・説明・中身を **0.07秒ずつずらして**出すと、組み上がって見えます。

| | 遅れ |
|---|---|
| 小見出し | 0秒 |
| 見出し | 0.07秒 |
| 説明文 | 0.14秒 |
| カード1〜4枚目 | 0.12 / 0.20 / 0.28 / 0.36秒 |
| ボタン | 0.50秒 |

### ホバーのしかた

**薄くなるのは 0.06秒、戻るのは 0.5秒。** ゆっくり薄くなるとためらって見えます。
押した感じを出すには、行きを速く、戻りを緩めます。

画像は **0.9秒かけて 1.055倍**だけ寄ります。動きが大きいと安く見えます。

## コラージュ・ヒーロー（縦書き＋斜め写真）

「＋ ブロックを追加」→ **コラージュ（縦書き＋斜め写真）**。
写真を敷き詰めた背景に、斜めに切り出した写真と、縦書きの白い帯を重ねます。
イベント・採用・特集の顔に向く型です。

- **縦書きの帯**は右寄せ・左寄せの2組。**1行＝1列**で、
  日本語の縦書きどおり最初の行がいちばん右に来ます
- **写真**は1つのリストにまとめて入れます。先頭の数枚（2〜5枚）が
  手前に斜めで出て、全部が背景の敷き詰めに回ります
- 背景の暗さ・色を抜くか・ゆっくり浮かせるか・高さ を選べます

### 縦書きは writing-mode を使っていません

`writing-mode:vertical-rl` は、縦書き用の字送り（vmtx）を持たないフォントに当たると
**漢字の送りがゼロになり、字が重なって潰れます。** この環境で実測したところ、
「緑を感じながら、」の漢字2文字が高さ0で、かなだけが送られていました
（Times / serif / sans-serif のどれでも同じ）。

そのため**1文字ずつ積む**方式にしています。どのフォントでも同じ見た目になります。
縦書きの決まりごとは個別に処理しています。

- 長音符・括弧・ダッシュ（`ー（）「」…`）は90°回す
- 句読点（`、。`）は枡の右上に寄せる

### 背景のタイルは背景画像で描いています

`<img>` を72枚並べると、写真の data URI が**枚数ぶん複製**されて、
書き出したHTMLが何MBにも膨らみます。URIはセクションのCSS変数として
1回だけ置き、タイルは `background-image:var(--cp3)` のように参照するだけにしています。

### 斜めの写真

枠を傾けて中身を逆に戻すと、四隅が内側に食い込んで余白が出ます。
中身を `|sinθ|+|cosθ|` 倍にしておけば、どの角度でも隙間なく埋まります。
この倍率は生成時に角度から計算して `--cov` で渡しています。

## スクロール連動ヒーロー（4種）

ヒーローを画面に貼り付け、スクロールの進み具合（0〜1）で動かします。
右パネルの「スクロール連動」、または **「▦ サンプルを見ながら選ぶ」** から選びます。

| 型 | 動き |
|---|---|
| 写真が縮んで枠に収まる | 全画面の写真が、角の丸い1枚に収まる。文字は上に抜けて消える |
| 写真と文字がずれて流れる | 写真はゆっくり、文字は速く。奥行きが出る |
| 幕が上下に開く | 閉じた幕が割れて写真が現れる |
| 文字の中から写真が広がる | 見出しの形に開いた穴が広がり、画面いっぱいの写真になる |

「動ききるまでの長さ」で 120〜320% の区間を取れます（長いほどゆっくり）。
動ききると、そのまま次のセクションにスクロールが渡ります。

見本は `examples/hero-scroll.html`（`node examples/build-scroll-demo.js` で作成）。

### 作り

JSがやるのは1つだけです。区間の進み具合を `--p`（0〜1）としてセクションに書き込む。
動きはすべてCSS側の `calc()` で書いてあるので、型を足すときはCSSだけで済みます。

```css
.hsc-zoomout .hero-bg{ inset: calc(var(--p,0) * 7vh) calc(var(--p,0) * 9vw) }
```

- スクロールの購読は既存の1本のrAFにまとめています（型ごとに増えません）
- 同じ値なら書き込みません（無駄な再計算を避けるため）

**「文字の中から写真が広がる」は、写真を文字で塗る方法を使っていません。**
`background-clip:text` で写真を文字に塗って拡大すると、写真が引き伸ばされて
ひどく粗くなります。代わりに、写真は等倍のまま置き、その上に
**文字の形だけ穴が開いた板**をかぶせて穴のほうを広げています。
穴はSVGなので、何倍に広げても輪郭がぼやけません。

なお、CSSの `mask` は画像を渡すと「明るさ」ではなく「不透明度」で見ます。
黒い文字を置いただけでは穴になりません（板が真っ黒のまま出ます）。
SVGの中で先に `<mask>` で抜いてから渡しています。

### 貼り付けと暗幕

文字を守る暗幕は通常 `.hero.cover::before` に入っていますが、スクロール型では
その擬似要素が「縦に長いセクション」に付くため、一緒に流れてしまいます。
貼り付く側（`.wrap`）に置き直しています。

### 装飾が文字を邪魔しない仕組み

装飾レイヤーは `z-index:0`。写真より上、**文字を守る暗幕より下**に入ります。
そのため、どれを選んでも見出しのコントラストは落ちません。

字の下の画素だけを取り出して測って確かめています（文字を出した絵と消した絵の
差分を取り、変化した画素＝字とみなす方式）。装飾なしの状態と比べて差はありません。

| | 下位5% | 中央 |
|---|---|---|
| 装飾なし | 2.41 | 6.67 |
| すりガラス | 2.09 | 7.58 |
| ふわふわ雲 | 2.47 | 7.00 |
| スポットライト | 2.69 | 8.32 |

下位5%が2前後なのは、写真の上に白文字を置いたときの縁の画素によるものです。
装飾なしでも同じ値になります。

### ポインタ追従の作り

生の座標をそのまま使うとカクつくので、毎フレーム少しずつ目標に寄せています
（大きいガラスは遅く、小さいガラスは速く）。この「遅れ」が重みになります。

- 動きが止まったら `requestAnimationFrame` も止めます
- 指の環境（`hover:none`）では追従を切り、中央に置いたままにします
- 「動きを減らす」設定では、装飾は動かない1枚の絵として残します
- 光の粒は、画面の外に出ると描画を止めます

### 写真の上の文字について

背景いっぱいの写真の上に文字を置くとき、平らな暗幕だけでは
写真の明るい部分で文字が読めなくなります。そのため、

- 文字が乗る中央だけをもう一段暗くする（写真の四隅は明るいまま）
- 見出しと説明文に薄い影を付ける
- 「誌面のような」造形では下線だけのボタンが濃色になるので、写真の上では白に切り替える

という処理を入れています。実際に描画された画素で測って、
いちばん明るい部分でもコントラスト比 5.0 以上になることを確認しています。

### 行末に1文字だけ残るのを防ぐ

日本語は単語の切れ目が無いぶん、最終行に1〜2文字だけ取り残されやすくなります。
見出しと短いリード文、紹介文の段落には `text-wrap:balance` を指定して、
行の長さがそろうようにしています。
