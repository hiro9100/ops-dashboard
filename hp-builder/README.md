# かんたんHP作成ツール

テンプレートを選んで、中身を差し替えるだけで自分のホームページが作れるツールです。
できあがったサイトは **HTML1ファイル** として書き出せます。

## 使い方（プロンプトは一切不要です）

`hp-builder/index.html` をブラウザで開くだけ。ビルドもサーバーも不要です。

1. **業種・名前・写真をえらぶ** — 起動時のかんたんモード（下記）。
   テンプレートから選ぶことも、部分ごとに組むこともできます
2. **左でページの構成をいじる** — ブロックをドラッグして並べ替え。
   「＋ ブロックを追加」はサンプル付きの一覧から選びます
   （選択中のブロックの下に入るので、あとからドラッグで動かせます）
3. **右で中身を編集** — テキスト・画像・色。プレビューに即反映されます
4. **HTMLを書き出す** — `index.html` がダウンロードされる。そのままサーバーに置けば公開できます

- 編集内容はブラウザに自動保存されます（次に開くと続きから）
- プレビューの文字を**ダブルクリック**すると、その場で書き換えられます
  （Esc で取り消し、外をクリックまたは Ctrl/⌘+Enter で確定）
- プレビューの文字や画像を**1回クリック**すると、その要素にアニメーションを付けられます
  （青い枠＝テキスト、紫の枠＝画像・カード。ラベルが出るのでどこを触っているか分かります）
- ヘッダーとフッターは位置が決まっているので、ドラッグの対象外です
- 「最初から」でぜんぶ消してテンプレート選択に戻ります

## かんたんモード（起動時の正面）

対象は「いまホームページを持っていない人」です。文章を書く、配色を決める、
写真をどこに置くか考える——そのどれもさせません。

```
① 業種をえらぶ   10種から1タップ
② 名前を入れる   1回入力
③ 写真をえらぶ   まとめて選ぶだけ
                → できあがり
```

- **文章** — 業種ごとに書いてあります。店名は `${n}` の位置に差し込まれます
- **写真** — 上のブロックから順に入ります。1枚目がヒーロー、以降は紹介・ギャラリーへ。
  ロゴ枠には入れません（社名の横に店内写真が並んでしまうため）
- **配色** — 写真から色みを拾います。ただし借りるのは色みだけで、明るさと鮮やかさは
  こちらで決め直します。背景に対して contrast 4.5 以上になるまで明るさを動かし、
  それでも届かない色みなら土台の配色のまま使います（読めない色を出さないため）

背景が暗いテンプレートでは、色を暗くするのではなく明るくします。
逆方向に動かすと読めなくなるためです（`bistro` と `demolition` で実際に起きました）。

業種を足したいときは `assets/easy.js` の `INDUSTRIES` に1つ追加します。
土台にするテンプレートのキーと、被せる文章を書くだけです。

## 部分ごとに選んで組む

まるごと1ページのテンプレートではなく、**1段ずつ選んで積み上げる**やり方もできます。
テンプレート選択の画面から「部分ごとに選んで組む」で入ります。

1. **ヒーローを選ぶ**（14型）— 中央ぞろえ・写真いっぱい・すりガラス・
   スクロールで写真が縮む・文字の中から写真が広がる、など
2. **ブロックを選ぶ**（28型）— 選ぶと下に積まれます。必要なだけくり返します
3. **「これで完成」** — 通常の編集画面に移り、そこから中身を書き替えます

選ぶたびに後ろのプレビューが伸びるので、**出来上がりを見ながら次を決められます**。
上部の帯に、いま積んだものが選んだときの名前で並びます。「1つ戻す」で直前の1段を
取り消し、「やめる」で入る前の状態に戻ります。順番はあとから並べ替えられます。

### 名前と分けかたは「かたち」で付ける

選ぶ基準は**使い道ではなく、かたち**です。
「よくある質問」ではなく「押すと開く一覧」、
「会社紹介」ではなく「写真 左 ／ 文章 右」。

使い道は人によって違います（同じ「押すと開く一覧」を、質問にも料金の内訳にも
使う人がいる）。かたちは見たままなので、初めての人でも迷いません。
何に使えるかは説明文に添えます。

分類も同じ考えで、`すべて／写真／横に並べる／縦に並べる／文章・帯／その他` の
6つだけです。業種では分けません。

```js
{ key: 'features-paren', type: 'features', group: 'カード',
  label: 'カード2つ（( 01 ) つき）',
  about: '番号を控えめに置く形。落ち着いて見える。',
  props: { style: 'paren', cols: 'c2' } },
```

「型」はブロック種別と初期値の差分でできています（`assets/presets.js`）。
同じ `features` でも、アイコン3列と `( 01 )` 形式は別の型として並びます。
見本は `BLOCKS[type].render()` で実物を描いているので、ここに書いた差分が
そのまま見た目に出ます。型を足したいときは配列に1つ追加するだけです。

### 見本はいつも「広い画面の並び」で描く

見本の中身は生成サイトと同じCSSなので、メディアクエリが効きます。iframe を
画面幅のまま置くと、スマホでは iframe 自体が狭いと判定され、「写真 左 ／ 文章 右」
が縦積みで出てしまいます。名前とかたちが食い違うと、かたちで選べません。

そこで iframe を 1180px の幅で描かせ、丸ごと縮めて枠に収めています
（`galGeom` / `sizeGalFrame` / `galleryCSS`）。縮む分、カードの文字と余白は
1/縮尺 倍にして、画面上の見た目を保っています。

配色は無彩色寄りのものから始まります。デザインタブでいつでも入れ替えられます。

## ヘッダーのバー（6種）

ヘッダーを選ぶと「バーの型」が出ます。「サンプルを見ながら選ぶ」で、
**いま使っているヘッダー**を型ごとに並べて比べられます。

| 型 | 見え方 |
| --- | --- |
| 線だけ（既定） | 地の色に細い線。固定しているときは半透明になる |
| ベタ塗り | メインカラーで塗り、文字とメニューを白に。ボタンは白抜き |
| すりガラス | 下の中身が透ける。ぼかしが入る |
| 無色（透ける） | 地も線もなし。流れの中には残る |
| ヒーローに重ねる | 流れから外してヒーローの上に置く。写真が画面の上端から始まる |
| 浮かぶ島 | 角の丸い島が浮く。地は擬似要素で敷く |

既定の `line` は、この機能を足す前の見た目そのままです。前に作ったページの
見え方は変わりません。

**重ねる型の文字色は、下を見てから決めます。** すぐ下が写真のヒーロー
（`.hero.cover` / `.hsc.cover` / `.collage`）のときだけ `on-photo` が付いて白字に
なります。地の明るいヒーローに白字を出すと読めないためで、判定は書き出した
HTMLの中の JS が行います（前の兄弟から次を見る CSS は、まだ全部の端末では
当てにできません）。重ねる型では「上に固定」は効かないので、設定欄も出しません。

バーの型のCSSは、スタイルやテンプレートの味付け（`.sty-*` / `.tpl-*`）より
**後ろ**に置いています。同じ強さの指定なので、後ろに書いたほうが勝ちます。
これを前に置くと「無色を選んだのに味付けの線が残る」が起きます（実際に起きました）。

## 写真の形（12種）

写真を持つブロック（ヒーロー・紹介・ギャラリー・カード・フロア・横に流れる）に
「写真の形」が出ます。

`四角のまま／角を大きく丸める／丸／アーチ／木の葉／六角形／斜めに切る／たまご`

さらに、曲線のある**デザイン寄りの4種**：
`4本の柱（上下が交互に丸い）／3連アーチ／下が波／まるいかたまり`

**絵から作った3種**：`丸つなぎ（3×3）／斜めの帯／音の波（縦の棒）`

この3つは、手で書けるSVGでは出せない形（丸どうしが溶けてつながる、帯が
重なる）なので、絵そのものを抜き型として持っています（`assets/shape-masks.js`）。
持ち込まれた画像を、下の「自分で用意した形」と同じ手順で変換して焼き込んだものです。

ページに焼き込むのは**実際に使われている形だけ**です（`usedShapes()` →
`shapeMaskCSS()`）。1つ5〜8KBあるので、使っていない形まで毎回付いてくると
書き出したHTMLが無駄に重くなります。四角に戻せばCSSごと消えます。

そして **「自分で用意した形」**。形の画像を読み込むと、**その形どおりに抜きます**。

- 透明を含む絵（PNGなど）… その透明をそのまま使う
- 透明を含まない絵（白地に色の形など）… ふちから背景をたどって外し、残ったところを形とみなす

どちらも最後は「形のところだけ不透明」の絵になり、`mask-image` に敷きます。
長辺560pxまで縮めてWebPで持つので、抜き型1つは数KBです。
値はブロックの `style` に `--shape` として出るので、書き出したHTMLでも効きます。

こちらは多角形（`clip-path:polygon`）では出せないので、SVGの絵をマスクとして
敷いています。SVGはCSSの中に文字として入れてあるので、外から読み込むものは
増えません（`file://` でもそのまま動きます）。`preserveAspectRatio='none'` と
`mask-size:100% 100%` で枠の形に合わせて伸び縮みします。

**写真そのものは触りません。** 枠の側を `clip-path` と `border-radius` で抜くだけなので、
いつでも四角に戻せますし、書き出したHTMLも軽いままです。抜くのは枠
（`.hero-media` など）で、中の `img` ではありません。枠には下地の色が敷いてあるので、
`img` だけを抜くと下地が形の外に残ります。

背景いっぱいのヒーロー（`cover`）には効かせていません。画面の角が欠けるだけだからです。

## 写真の位置と大きさ

ヒーローは **4つの型すべてで写真を出します**。以前は中央ぞろえ・左ぞろえのとき
画像を入れても何も起きず、入れた本人には壊れて見えていました（指摘されて直しました）。
いまは文章の下に横いっぱいの一枚を置きます。写真いっぱいの型にも枠の目印を付けたので、
押せば選び直せますし、位置と大きさの調整も届きます。

**プレビューの写真をクリック**すると、右の欄が「写真」に変わります。

| | |
| --- | --- |
| 大きさ | 100〜260%。枠いっぱいまで寄せる |
| 横の位置 | 左 ↔ 右（`object-position` の X） |
| 縦の位置 | 上 ↕ 下（`object-position` の Y） |

枠に入りきらない分は切れるので、顔や商品が切れているときはここで寄せます。
「まん中・等倍に戻す」で既定に戻り、そのとき値そのものを捨てるので、
書き出したHTMLに余計な指定は残りません。

写真がすでに入っている枠をクリックしたときは、**写真選択を開きません**。
位置を直したいだけのときに毎回ファイル選択が出てしまうためで、
選び直したいときは欄の中の「写真を選び直す」を押します。
まだ写真の無い枠は、これまでどおり押すとすぐ選択が開きます。

値は枠の `style` に CSS変数（`--ix` / `--iy` / `--iz`）として書き出されます。
編集用の目印（`data-imgprop`）は書き出しで落ちますが、`style` は残るので、
公開したページでもそのまま効きます。一覧の中の写真（ギャラリーやカード）も
1枚ずつ別々に調整できます。

## 背景をぬく

写真を1枚入れると「背景をぬく」が出ます。**端末の中だけで処理し、写真はどこにも送りません。**

やり方は「**ふちから**、背景に近い色をたどって消す」です。全体から背景色に近い画素を
消すやり方だと、被写体の中の白（皿・服・歯）まで抜けてしまいます。ふちからつながって
いる画素だけを消せば、それが起きません。

- 効くもの … 白い壁・単色の背景、商品写真、ロゴ
- 効かないもの … 人物、雑多な背景（きれいに抜くには学習済みモデルが要ります）
- ぬく範囲はスライダーで調整でき、「背景と判断したところ ○%」が目安に出ます
- 入れたあとでも「取り消し」で元の写真に戻せます

書き出しは **WebP（透過つき）**です。PNG は写真だと非常に重く、512pxの写真でも 255KB に
なりました（1ページ3MBの上限に当たります）。同じ写真が WebP なら 16KB です。
WebP を作れない環境では PNG に落ち、それでも 700KB を超えるときは縦横を縮めます。

### 配色だけ入れ替える（14パレット）

テンプレートを選び直すと中身まで置きかわってしまいます。
「構成はこのままで色だけ変えたい」ときは、デザインタブの
**「▦ 配色を一覧から選ぶ」** を押してください。

- 一覧のカードには、**いま作っているページの上から3ブロック**がその配色で描かれます。
  よその見本ではなく自分のページで見比べられます。
- 選ぶと変わるのは色の8項目（メイン／アクセント／背景／面／文字／補助文字／罫線／濃色）だけです。
  角の丸み・横幅・フォント・造形の型・ブロックの並びはそのまま残ります。
- いま使っている配色と一致するカードには枠が付きます。
- 取り消し（Ctrl+Z）で戻せます。

### デザインの型

配色だけでは似た顔になるため、**造形そのもの**を切り替える仕組みを入れています。
デザインタブの「全体の造形」から、あとで変えることもできます。

| 型 | 変わるところ |
|---|---|
| 標準 | 影と丸みのある一般的な見た目 |
| モノクロ調 | 影をなくし罫線で区切る。見出しは左寄せ、小見出しに赤い罫、角ゼロ |
| やわらかい | 影を大きく、角を丸く、アイコンを円形の下地に載せる |
| 太い | 見出しを大きく重く、小見出しをラベル化 |
| 誌面のような | 余白を広げ、箱をなくして罫線だけに。ボタンは下線 |

### 文字色の自動調整

メインカラーの明るさを測って、その上に置く文字色（`--c-on-primary`）を白か黒に自動で決めています。
黄色などの明るい色をメインにしても、帯やボタンの文字が読めなくなりません。

## 使えるブロック

ヘッダー / ヒーロー / 特徴・サービス / 紹介（画像＋文章） / ギャラリー /
コラージュ（縦書き＋斜め写真） / お品書き（価格表） / フロアガイド /
お知らせ・イベント / 流れる文字 / 料金プラン / よくある質問 / CTA帯 /
お問い合わせ / 自由テキスト / フッター

### お知らせ・イベント

日付・カテゴリ・見出しを1行に並べた一覧です。行にポインタを乗せると少し右にずれます。
「もっと見る」ボタンは、文字を空にすると消えます。
狭い画面では見出しだけが次の行に落ちます。

### フロアガイド

階ごとに「階数・名前・説明・画像」を並べます。商業施設・ビル・複合施設向けです。
偶数番目は左右が入れ替わり、狭い画面では縦積みになります。

### 流れる文字（マーキー）

同じ言葉が横に流れ続ける帯です。区切りのしるしや、お問い合わせの手前に置きます。

- 速さ（1周8〜60秒）・向き（左／右）・文字の大きさを変えられます
- **中を抜いた文字**にすると、線だけになるぶん大きく置いてもうるさくなりません
- リンク先を入れると帯ごとリンクになります。ポインタを乗せると止まります

途切れずに流すため、同じ並びを2組ならべて1組ぶんだけ動かしています。

### 縦の罫線（デザインタブ）

左・中央・右に細い線を通すと、全体が図面のように締まります。
画面に固定しているのでスクロールしても動きません（スマホでは左右の2本だけ）。

### お品書き（価格表）について

カフェ・飲食店・サロン向けの、品名と価格を並べるブロックです。
カテゴリ（COFFEE / FOOD など）ごとにまとめ、品名と価格を点線でつなぎます。

品目は1行に1品、**「品名 | よみ | 価格」**のように縦棒で区切って書きます。

```
Drip Coffee | ドリップコーヒー | 550
Café Latte | カフェラテ | 600
```

縦棒が足りない書き方（`ドリップコーヒー | 550` など）でも壊れません。
最後のひとつを価格、先頭を品名として扱います。

品名が長くて折り返しても、価格は右端にそろったままです。
カテゴリの右肩には「HOT / ICED」「サラダ・スープ付」のような注記を置けます。

**スクロールに連動する特別なブロック（9種）**

| ブロック | 内容 |
|---|---|
| 3D製品ビュー | スクロールで立体が360°回転。画像不要、形と色だけで作られます |
| 分解図が組み上がる | バラバラの層が合体。各層に画像を入れられます |
| 横に流れるギャラリー | 縦にスクロールするとカードが横に流れます |
| 積み重なるカード | カードが重なりながら積み上がります |
| タイムライン | 線が伸びて、通過した項目が点灯します |
| 円形マスクで切り替え | 円が開いて下の世界に入れ替わります |
| 3Dカルーセル | 円環に並んだカードが回ります。ドラッグでも回せます |
| 数字カウンター | 桁ごとに数字が縦に回って止まります |
| 線が引かれるグラフ | 棒グラフと折れ線が線を引くように現れます |
| 全画面メッセージ | 画面いっぱいに1つの言葉。色を変えると空気が変わります |
| スライドページ | スクロール1回で1枚めくる全画面スライド（下記） |

### スライドページについて

「1スクロール＝1枚だけ進む」「表示のたびに図と数字を最初から再生」を満たすブロックです。
左に動く図（棒グラフが伸びる / 線が描かれる / 円が満ちる）、右に番号・見出し・
リード文・箇条書き・大きな数字を置きます。右端に固定のドットナビが出ます。

**ページ全体を乗っ取る作りにはしていません。** 元の仕様は `html,body{overflow:hidden}` で
ページ全体をスライドにする前提でしたが、それだとヘッダーも他のブロックも置けなくなるため、
固定セクションの中でめくる方式にしています。結果として「最初と最後ではスクロールが
前後のセクションに渡る」は自動的に満たされ、慣性スクロールで突き抜けるガードも不要です。

スマホ（768px以下）では縦積みの通常スクロールに切り替わり、
各スライドが画面に入るたびにアニメーションが再生されます。

「＋ ブロックを追加」を押すと、**実物のサンプルが並んだ一覧**が開きます。
カテゴリ（基本 / スクロール連動 / 3D / 数字・図解 / 演出）で絞り込めます。
サンプルは生成サイトと同じCSSでその場に描いているので、見たままが入ります。

各ブロックには「背景色」と「アンカーID」があります。
アンカーIDに `about` と入れておけば、メニューのリンク先に `#about` と書くだけで
そこまでスクロールするようになります。

## 画像について

入れかたは3通りです。

1. **プレビューの画像枠をタップ / クリック** — 端末の画像選択が開きます
   （スマホならカメラロール）。いちばん手数が少ない方法です
2. **画像ファイルを枠にドラッグ&ドロップ**（パソコン）— 枠が紫の点線に変わったら放します
3. 右パネルの「画像を選ぶ」ボタン、または画像URLを直接入力

取り込むときに**長辺1600pxまで縮小**し、JPEGに変換します。スマホの写真は
そのままだと数MBあり、ブラウザの保存上限をすぐ超えてしまうためです。
400KB以下かつ1600px以下の画像は、変換せずそのまま使います。
SVGとGIFは描き直すと壊れる（ベクタ / アニメーション）ので変換しません。

写真の向き（EXIF）は `createImageBitmap` の `imageOrientation` で補正しています。

- 画像はデータURLとしてHTMLに直接埋め込まれます。1ファイルで完結する代わりに、
  枚数が増えるとファイルも重くなります
- 自動保存の上限（おおむね5MB）を超えると保存だけができなくなります。
  編集と書き出しは続けられるので、その場合はHTMLを書き出してください
- 未設定の画像枠には `IMAGE` のプレースホルダが出ます

## 公開する

対象の利用者にとって、ここが最後でいちばん高い壁です。
「HTMLを書き出しました」で放り出すと、その先に進めません。

「公開する」を押すと、3画面で公開先まで連れて行きます。

1. **公開先を選ぶ** — Netlify Drop（いちばん簡単）／ GitHub Pages ／ 持っているサーバー
2. **手順を1手ずつ** — 押すボタンをその場に置きます（書き出す・公開先を開く）
3. **アドレスを控える** — 次からは公開ずみの画面から始まり、更新のしかたが出ます

控えたアドレスは `<link rel="canonical">` と `og:url` として書き出しに入ります。

### そのまま公開する（Firebase）

`assets/publish-config.js` に公開先を設定すると、選択肢の先頭に
**「このまま公開する」** が出ます。押すだけで公開まで終わり、
アドレスがその場で出ます。登録もファイルの置き場所も要りません。

仕組みと出し方は `firebase/README.md` にまとめてあります。要点だけ:

- 持ち主の証明は**合言葉**だけ。ログインを求めません
- 合言葉は**手元にダウンロードするHTMLにだけ**入れ、公開する版からは外します
- 編集ツールは Firebase SDK を読み込みません。公開のときに `fetch` を1回するだけです
- 設定を空にすると、この道は消えて「自分で置く」だけになります

### まだできないこと

既存サイトのURLを読み込んで作り直す機能は作れません
（ブラウザからは他所のサイトを読めません）。

## 保存と持ち運び

編集中の内容はブラウザに自動保存されますが、**それだけでは端末を替えると消えます**。
そこで、**書き出したHTML自身が控えを兼ねる**ようにしています。

- 「HTMLを書き出す」で出したファイルを、「HTMLを開く」から読み込めば続きから編集できます
- パソコンなら、画面にファイルを放り込んでも開きます
- 起動直後の画面にも「作ったHTMLを開く」を置いています。
  この画面が上部バーを覆っていて、そちらのボタンを押せないためです

スマホで書き出したファイルをパソコンに送れば、そのまま続きを編集できます。
サーバーもログインも要りません。利用者が管理するファイルは1枚のままです。

### 写真を二重に持たない

組み立て情報は `<script type="application/json" id="hp-builder-data">` に入ります。
ただし写真をそのまま入れると、本文とあわせて倍の重さになります。

そこで本文に出てくるデータURLを出てきた順に数えて、控えの側は
`@@hpimg:0` のような**番号だけ**を持ちます。読み込むときに番号から戻します。
写真4枚（317KB）のページで、書き出しは407KBでした（二重なら700KB超）。

数える範囲は本文だけに揃えています。生成サイトのCSSに
`data:image/svg+xml` が1つ入っているため、文書ぜんぶを数えると番号が1つずれます。

本文に出てこない写真（表示されない項目に入っているものなど）は参照しようがないので、
控えの側にそのまま持たせます。

## 公開する

リポジトリ直下の `docs/` に、そのまま置けば動く一式が入ります。
ビルドもサーバー処理も要りません。

```
node build-site.js     # docs/ を組み立てる
node verify-site.js    # 公開後と同じHTTP越しに確認（要 playwright）
```

できあがり：

| パス | 中身 |
| --- | --- |
| `docs/index.html` | サービスLP（入口） |
| `docs/app/index.html` | 編集ツール本体（1ファイル） |
| `docs/demo/` | 作例4種と、その入口ページ |

**GitHub Pages で出す** — Settings → Pages → Source を「Deploy from a branch」、
ブランチを選び、フォルダに **`/docs`** を指定。数分で
`https://<ユーザー名>.github.io/<リポジトリ名>/` に出ます。

出力先がリポジトリ直下なのはこのためです。ここで選べるフォルダは
「/（リポジトリ直下）」と「/docs」の2つだけで、`hp-builder/docs` のような
深い場所は選択肢に出てきません。

**それ以外** — Netlify・Vercel・レンタルサーバーのいずれも、`docs/` の中身を
そのままアップロードするだけです。ビルドコマンドの設定は要りません。

`docs/.nojekyll` は、GitHub Pages が既定で通す Jekyll を止めるための空ファイルです
（`_` で始まる名前などが消されるのを防ぎます）。

## 増やしたいとき

**ブロックを増やす** — `assets/blocks.js` の `BLOCKS` に1つ足します。
`fields` を書けば編集フォームは自動で生成されます（`text` / `textarea` / `select` /
`toggle` / `color` / `range` / `image` / `list`）。最後に `ADDABLE` へキーを追加。

```js
news: {
  label: 'お知らせ', icon: '!',
  fields: [ FIELD.title, { key:'items', type:'list', item:[ ... ] }, FIELD.bg, FIELD.anchor ],
  defaults: { title:'お知らせ', items:[], bg:'', anchor:'news' },
  render: (p) => sec('news', p, `...HTML...`),
}
```

**テンプレートを増やす** — `assets/templates.js` の `TEMPLATES` に、配色（`theme`）と
初期ブロック（`blocks`）を書きます。`blocks` には各ブロックの `defaults` からの
差分だけ書けばOKです。

## 制約

- 1ページ構成のサイト向けです（複数ページはブロックを組み替えて別々に書き出してください）
- お問い合わせフォームは見た目だけです。実際に送信するには、送信先URL欄に
  Googleフォームなど外部サービスのURLを設定してください
- 保存先はブラウザのlocalStorageなので、別のPC・別のブラウザには引き継がれません

## 取り消し / やり直し

左上の `↶` `↷`、または **Ctrl/⌘+Z**（やり直しは **Ctrl/⌘+Shift+Z**）。
プレビューの中にフォーカスがあるときも効きます。

- 並べ替え・追加・削除・文字の書き換え・アニメの設定・配色まで、すべて戻せます
- 文字入力は連続した打鍵を1回分にまとめるので、1回の取り消しでまとめて戻ります
- 入力欄や直接編集の最中は、ブラウザ本来の文字取り消しを優先します
- 取り消したあとに別の操作をすると、それ以降のやり直しは消えます（通常の編集ソフトと同じ）

履歴は state の丸ごとコピーを積む方式です。画像をデータURLで持てるため、
40件かつ合計12MBの上限を設け、超えた分は古いものから捨てています。

## スマホでの編集

820px以下では、3カラムから「プレビュー1枚＋下から出るシート」に切り替わります。

- 下部ナビ: **構成 / 編集 / デザイン / 追加 / 書き出す**
- プレビューの要素をタップすると、編集シートが自動で開きます
- 文字の編集は、要素をタップ →「✎ 文字を編集」（プレビューのダブルタップでも可）。
  キーボードで隠れないよう、編集を始めるとシートは閉じます
- 並べ替えは `⠿` を指で掴んで上下に動かします。一覧の端まで運ぶと自動でスクロールします
- タップ環境ではホバーが無いため、↑↓・複製・削除のボタンは常に表示されます

指でのドラッグは HTML5 のドラッグ&ドロップが効かないため、Pointer Events で別に実装しています。
移動と終了は document 側で受けており、`setPointerCapture` が使えない環境でも最後まで追えます。

## 動き（アニメーション）

デザインタブの「動き」で、サイト全体の見た目に動きを付けられます。

- **見出しの文字アニメ** — 12種類（なし / フェードアップ / 行マスクせり上げ / ぼかし解除 /
  3Dフリップ / 回転して落ちる / 弾む / 左右交互スライド / 散らばりから集合 / ネオン点灯 /
  グラデーションで塗る / スクランブル / タイプライター）。すべての見出しに適用されます
- **アニメの長さ・1文字ごとのずらし・イージング** — 速さと質感の調整
- **ブロックをスクロールで出現させる** — 各セクションが下からふわっと現れます

### 寸法は画面幅に比例させています

**1440pxを基準に比例、2000pxで頭打ち**という作り方にしています。
参考にした制作会社のサイトはどれもこの方式でした。

```
min(100vw / 1440 * 56, 2000/1440 * 56px)   ← 見出し56pxの場合
```

これをやらないと、**広い画面でデザインが伸びるのをやめます。**
以前は1920pxでも1440pxとまったく同じ寸法で、余白だけが左右に余っていました。

| | 1024px | 1440px | 1920px |
|---|---|---|---|
| 見出し | 39.8px | 56px | 74.7px |
| 節見出し | 22px | 30px | 40px |
| 本文 | 15px | 18px | 24px |
| 節の上下余白 | 93.9px | 132px | 176px |

`clamp()` の下限はそのまま残してあるので、狭い画面で文字が小さくなりすぎることはありません
（390 / 1024 / 1920 / 2560px で、11px未満の本文が0件・横はみ出し0件を確認）。

**1440pxでの見た目は1pxも変えていません。** いまのデザインを保ったまま、
比例するようにだけ直しました（43箇所を機械的に変換）。

### 慣性スクロール

デザインタブの「動き」から入れられます（初期状態は入り）。
ホイールを止めたあとも少し滑ってから止まります。
高い制作費のサイトの「手触り」は、装飾よりここで決まります。

**中身をまるごとずらす方式は使っていません。** よくある実装は `wrapper` を
`transform` でずらしますが、それだと `position:sticky` が効かなくなります。
このツールは貼り付くブロック（横に流れるギャラリー、スクロール連動ヒーロー、
積み重なるカード）を多く持つので、**ページ本来のスクロール位置そのものを
なめらかに動かす**方式にしました。sticky も IntersectionObserver もそのまま動きます。

- マウスのある環境だけで働きます。指の操作では切れます
- 「動きを減らす」設定では切れます
- 中でスクロールできる箱（コード表示など）の上では、そちらに任せます
- キーボードやアンカーで飛んだときは、目標位置を合わせ直します

書き出したHTMLでもそのまま働きます。

### 出現のしかた

ブロックごと一度に出すと「表示された」で終わります。
見出し・説明・中身を **0.07秒ずつずらして**出すと、組み上がって見えます。

| | 遅れ |
|---|---|
| 小見出し | 0秒 |
| 見出し | 0.07秒 |
| 説明文 | 0.14秒 |
| カード1〜4枚目 | 0.12 / 0.20 / 0.28 / 0.36秒 |
| ボタン | 0.50秒 |

### ホバーのしかた

**薄くなるのは 0.06秒、戻るのは 0.5秒。** ゆっくり薄くなるとためらって見えます。
押した感じを出すには、行きを速く、戻りを緩めます。

画像は **0.9秒かけて 1.055倍**だけ寄ります。動きが大きいと安く見えます。

### プレビュー上での直接編集

見出し・説明文・カードの文言・FAQ・料金プラン名・サイト名・コピーライトなど
37箇所をダブルクリックで書き換えられます。改行もそのまま反映されます。

文字アニメが付いている見出しは、編集を始めると一旦ふつうのテキストに戻り、
確定するとまたアニメーション付きで再生されます。

### 要素ごとに付ける

プレビューで要素をクリックすると、右パネルの一番上に専用の設定が出ます。

- **テキスト**（見出し・小見出し・説明文）— 文字アニメ12種
- **画像・要素**（画像枠・カード・料金プラン・ギャラリー）— ズームイン / ズームアウト /
  左から入る / 右から入る / 下から入る / 下から開く（ワイプ）/ 円形に開く / ぼかし解除 /
  3Dで起き上がる / めくれて立つ / ゆっくりズーム（ループ）/ ふわふわ浮遊（ループ）

どちらも「▦ サンプルを見ながら選ぶ」から、**実際に動くサンプルの一覧**で選べます。
くり返し再生されるので、名前だけでは分からない動きも見比べられます。
デザインタブの「見出しの文字アニメ」にも同じボタンがあります。

どちらも「開始までの待ち」を個別に設定できるので、
画像を先に出して見出しを少し遅らせる、といった演出ができます。

要素ごとの設定は全体設定より優先されます。

動きは書き出したHTMLにもそのまま入ります。文字の分割はJSが実行時に行うので、
書き出したHTMLのソースは読みやすいままです。JSが無効な環境では、
アニメーションは無効になりますが文章はそのまま表示されます。

各アニメーションを単体で試したい場合は `animations/text-lab.html`（14種・パラメータ調整可）へ。

ビルダー本体の `blocks.js` / `site-css.js` をそのまま読み込んで組み立てているので、
ブロックやCSSを直すと、この見本も同じように直ります。
「ショップ・カフェ」テンプレートの構成に、緑と生成りの配色と
「誌面のような」造形を合わせています。

| 節 | 使っているもの |
|---|---|
| ヒーロー | 外観の写真を背景いっぱいに |
| 紹介 | 店内の写真＋文章 |
| おすすめ3品 | 特徴ブロック（画像形式）。ラテ・ケーキ・プレートを1枚ずつ |
| お品書き | お品書きブロック。5カテゴリ17品 |
| テラス | ヒーローをもう一度使い、写真だけの「間」に |
| アクセス | 電話・メール・住所・営業時間＋予約フォーム |

写真6枚は `data:` URI で埋め込んであるため、このHTML1つだけで表示できます
（サーバーも画像フォルダも要りません）。全体で約470KBです。

## ヒーローの装飾（9種）

ヒーローだけは、他のブロックより一段こだわれるようにしています。
右パネルの「装飾の動き」、または **「▦ サンプルを見ながら選ぶ」** から選びます。
一覧には**いま編集中のヒーローがそのまま縮小して並び**、枠の中でポインタにも反応します。

| 装飾 | 動き |
|---|---|
| ふわふわ雲 | 光のかたまりがゆっくり漂う。ポインタで奥行きがずれる |
| すりガラス | 大小2枚のガラスがポインタを追い、背後の写真をぼかす |
| オーロラ | メインカラーとアクセントカラーが溶け合って流れる |
| 光の粒 | ゆっくり昇る粒。ポインタが近づくと押しのけられる |
| スポットライト | ポインタのまわりだけが明るくなる |
| 奥行き | 写真と文字が逆向きに動いて立体に見える |
| 流れる線 | 絹のような光の帯がゆっくり横切る |
| カーソルに丸がついてくる | ポインタを追う丸。中に「SCROLL」などの文字を置けます |
| フィルムの粒状感 | 単独ではなく、どの装飾にも重ねられる（トグル） |

「装飾の強さ」で全体の濃さを 10〜100% で調整できます。

見本は `examples/hero-deco.html`（`node examples/build-deco-demo.js` で作成）。
同じ写真で8種類を並べてあるので、マウスを動かして見比べられます。

## コラージュ・ヒーロー（縦書き＋斜め写真）

「＋ ブロックを追加」→ **コラージュ（縦書き＋斜め写真）**。
写真を敷き詰めた背景に、斜めに切り出した写真と、縦書きの白い帯を重ねます。
イベント・採用・特集の顔に向く型です。

- **縦書きの帯**は右寄せ・左寄せの2組。**1行＝1列**で、
  日本語の縦書きどおり最初の行がいちばん右に来ます
- **写真**は1つのリストにまとめて入れます。先頭の数枚（2〜5枚）が
  手前に斜めで出て、全部が背景の敷き詰めに回ります
- 背景の暗さ・色を抜くか・ゆっくり浮かせるか・高さ を選べます

### 縦書きは writing-mode を使っていません

`writing-mode:vertical-rl` は、縦書き用の字送り（vmtx）を持たないフォントに当たると
**漢字の送りがゼロになり、字が重なって潰れます。** この環境で実測したところ、
「緑を感じながら、」の漢字2文字が高さ0で、かなだけが送られていました
（Times / serif / sans-serif のどれでも同じ）。

そのため**1文字ずつ積む**方式にしています。どのフォントでも同じ見た目になります。
縦書きの決まりごとは個別に処理しています。

- 長音符・括弧・ダッシュ（`ー（）「」…`）は90°回す
- 句読点（`、。`）は枡の右上に寄せる

### 背景のタイルは背景画像で描いています

`<img>` を72枚並べると、写真の data URI が**枚数ぶん複製**されて、
書き出したHTMLが何MBにも膨らみます。URIはセクションのCSS変数として
1回だけ置き、タイルは `background-image:var(--cp3)` のように参照するだけにしています。

### 斜めの写真

枠を傾けて中身を逆に戻すと、四隅が内側に食い込んで余白が出ます。
中身を `|sinθ|+|cosθ|` 倍にしておけば、どの角度でも隙間なく埋まります。
この倍率は生成時に角度から計算して `--cov` で渡しています。

## スクロール連動ヒーロー（4種）

ヒーローを画面に貼り付け、スクロールの進み具合（0〜1）で動かします。
右パネルの「スクロール連動」、または **「▦ サンプルを見ながら選ぶ」** から選びます。

| 型 | 動き |
|---|---|
| 写真が縮んで枠に収まる | 全画面の写真が、角の丸い1枚に収まる。文字は上に抜けて消える |
| 写真と文字がずれて流れる | 写真はゆっくり、文字は速く。奥行きが出る |
| 幕が上下に開く | 閉じた幕が割れて写真が現れる |
| 文字の中から写真が広がる | 見出しの形に開いた穴が広がり、画面いっぱいの写真になる |

「動ききるまでの長さ」で 120〜320% の区間を取れます（長いほどゆっくり）。
動ききると、そのまま次のセクションにスクロールが渡ります。

見本は `examples/hero-scroll.html`（`node examples/build-scroll-demo.js` で作成）。

### 作り

JSがやるのは1つだけです。区間の進み具合を `--p`（0〜1）としてセクションに書き込む。
動きはすべてCSS側の `calc()` で書いてあるので、型を足すときはCSSだけで済みます。

```css
.hsc-zoomout .hero-bg{ inset: calc(var(--p,0) * 7vh) calc(var(--p,0) * 9vw) }
```

- スクロールの購読は既存の1本のrAFにまとめています（型ごとに増えません）
- 同じ値なら書き込みません（無駄な再計算を避けるため）

**「文字の中から写真が広がる」は、写真を文字で塗る方法を使っていません。**
`background-clip:text` で写真を文字に塗って拡大すると、写真が引き伸ばされて
ひどく粗くなります。代わりに、写真は等倍のまま置き、その上に
**文字の形だけ穴が開いた板**をかぶせて穴のほうを広げています。
穴はSVGなので、何倍に広げても輪郭がぼやけません。

なお、CSSの `mask` は画像を渡すと「明るさ」ではなく「不透明度」で見ます。
黒い文字を置いただけでは穴になりません（板が真っ黒のまま出ます）。
SVGの中で先に `<mask>` で抜いてから渡しています。

### 貼り付けと暗幕

文字を守る暗幕は通常 `.hero.cover::before` に入っていますが、スクロール型では
その擬似要素が「縦に長いセクション」に付くため、一緒に流れてしまいます。
貼り付く側（`.wrap`）に置き直しています。

### 装飾が文字を邪魔しない仕組み

装飾レイヤーは `z-index:0`。写真より上、**文字を守る暗幕より下**に入ります。
そのため、どれを選んでも見出しのコントラストは落ちません。

字の下の画素だけを取り出して測って確かめています（文字を出した絵と消した絵の
差分を取り、変化した画素＝字とみなす方式）。装飾なしの状態と比べて差はありません。

| | 下位5% | 中央 |
|---|---|---|
| 装飾なし | 2.41 | 6.67 |
| すりガラス | 2.09 | 7.58 |
| ふわふわ雲 | 2.47 | 7.00 |
| スポットライト | 2.69 | 8.32 |

下位5%が2前後なのは、写真の上に白文字を置いたときの縁の画素によるものです。
装飾なしでも同じ値になります。

### ポインタ追従の作り

生の座標をそのまま使うとカクつくので、毎フレーム少しずつ目標に寄せています
（大きいガラスは遅く、小さいガラスは速く）。この「遅れ」が重みになります。

- 動きが止まったら `requestAnimationFrame` も止めます
- 指の環境（`hover:none`）では追従を切り、中央に置いたままにします
- 「動きを減らす」設定では、装飾は動かない1枚の絵として残します
- 光の粒は、画面の外に出ると描画を止めます

### 写真の上の文字について

背景いっぱいの写真の上に文字を置くとき、平らな暗幕だけでは
写真の明るい部分で文字が読めなくなります。そのため、

- 文字が乗る中央だけをもう一段暗くする（写真の四隅は明るいまま）
- 見出しと説明文に薄い影を付ける
- 「誌面のような」造形では下線だけのボタンが濃色になるので、写真の上では白に切り替える

という処理を入れています。実際に描画された画素で測って、
いちばん明るい部分でもコントラスト比 5.0 以上になることを確認しています。

### 行末に1文字だけ残るのを防ぐ

日本語は単語の切れ目が無いぶん、最終行に1〜2文字だけ取り残されやすくなります。
見出しと短いリード文、紹介文の段落には `text-wrap:balance` を指定して、
行の長さがそろうようにしています。
