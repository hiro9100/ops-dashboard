# 決済・管理システム 乗り換えスケジュール表

アスリートクラス 運営 / 新システムへの移行手順と、引き落とし停止のデッドライン。

最終更新: 2026-07-30

---

## 0. 結論（これだけ守ればラグは出ない）

1. **クリティカルパスは口座振替**。カード決済は最短数日〜2週間で使えるが、口座振替は「審査 → 依頼書（またはWeb口振）回収 → 口座登録 → 初回請求データ提出」で**最低2ヶ月**かかる。ここから逆算する。
2. **旧側を止める最終期限＝旧側の「請求データ提出締切」**。締切を1分でも過ぎたら引き落としは止まらない（＝二重引落 → 返金対応）。多くの収納代行で **引落日の6〜14営業日前の正午** 。
3. **旧管理システム（SaaS）経由で請求している場合、SaaS側の締めはさらに早い**（引落日の20〜30日前が多い）。止める連絡はここに合わせる。あわせて**解約通知（通常30〜60日前・書面）**も別枠で必要。

> 二重引落と「1ヶ月抜け（無徴収月）」はどちらも起こる。**抜けるより二重のほうが復旧が楽**なので、判断に迷う月は旧側を1ヶ月長く回して差額を翌月調整するほうが安全。

## 1. 引き落とし会社別：引落日と「止める連絡」の期限

「止める最終期限」＝その月の請求データを出さない／取り消せる最後のタイミング。

| 引き落とし会社 / 方式 | 選べる引落日 | 請求データ提出締切（＝止める最終期限） | 止める連絡の実務目安 | 結果返却 / 入金 |
|---|---|---|---|---|
| **三菱UFJファクター（ワイドネット）** | 6日・12日・20日・26日・27日・月末（計6回） | **引落日の6営業日前 正午** | 締切の**3営業日前**までに担当へ「当月分データ提出を止める」と連絡 | 結果＝振替日+3営業日 / 入金＝振替日+6営業日（早期オプションあり） |
| **SMBCファイナンスサービス（SMBCマルチペイメント／口座振替）** | 27日固定型、またはセレクト型（5日・6日・23日・27日 ほか 8日・26日の組合せ） | セレクト型は**引落日の約2週間前 正午**（振替依頼受付期間の終了時刻）／27日固定型は所定締切 | 締切の**1週間前**までに連絡。紙の依頼書運用は前月27日着が別途必要 | 結果は振替日の約3営業日後以降に確認可 |
| **GMOペイメントゲートウェイ / GMOイプシロン（口座振替）** | 5日・6日・23日・27日 | **引落日の約14日前 正午**（例：9/27振替 → 受付は 8/15 正午〜9/13 正午） | 締切の**1週間前**まで。管理画面から請求登録を取消 | 振替日の約5営業日後から結果確認 |
| **リコーリース（集金代行 / コレクト！）** | 4日・20日・27日 | **要確認**（振替日の8〜10営業日前が一般的）。契約書添付の年間スケジュール表で確定 | 締切の**1週間前**まで。専用Webサイトで請求データを作らない＝止まる | 振替日の約6営業日後に入金 |
| **ロボットペイメント（サブスクペイ / RP口座振替）** | 10日・26日 | **引落日の前月26日 11:00**（例：12/10振替 → 11/26 11:00 まで） | 前月20日までに連絡。依頼書は初回引落の**前月末**までにJCB着 | 引落日の翌日から11営業日後に入金 |
| **ゆうちょ銀行 自動払込み** | 加入者が指定 | 通常は**払込日の10営業日前**目安／データ提出期限延長オプション利用時は**払込日の1営業日前 17:00** | 通常型なら**払込日の2週間前**まで | 振替日の数営業日後 |
| **銀行の自行口座振替（地銀・信金と直接契約）** | 契約で指定（27日型が主流） | **引落日の6〜10営業日前**（銀行の年間日程表による） | 銀行から配布される**年間日程表の「データ伝送期限」**を基準に、その1週間前 | 振替日+3〜6営業日 |
| **クレジットカード（継続課金 / サブスク）** | 課金実行日は加盟店指定（自由度高い） | **課金バッチ実行の前日まで**に定期課金を停止すれば止まる | 実行日の**3営業日前**までに旧システムの継続課金をOFF | 締め日により入金は15日〜翌月末 |
| **コンビニ払い・後払い（atone / NP後払い 等）** | 払込票の期限日 | 発券後は止められない → **発券前**に止める | 請求発行バッチの**前**（月初締めが多い） | 入金は締め後 |

### 使い方
- 自校が使っている行だけ残して、**「引落日」「締切」「うちの連絡期限」の3列を確定させる**のが最初の作業。
- 締切は**契約単位で個別設定されている**ことが多い。上表は公開情報ベースの目安なので、必ず**契約書または年間スケジュール表（振替日ごとのデータ伝送期限一覧）で確定**すること。

### 注意点
- 引落日が土日祝の場合は**翌営業日**に繰り越し（例：2026-12-27 は日曜 → 12/28 月曜）。締切も連動してズレる。
- 「6営業日前」は**祝日を含めて数える**。11月・1月・5月は祝日が多く、体感より2〜3日早まる。
- 締切は**正午（11:00の会社もある）**。「その日いっぱい」ではない。

## 2. 乗り換えスケジュール（工程順）

D = 新システムでの初回引落日。

| # | 工程 | 期限 | 担当 | 完了条件 / 注意 |
|---|---|---|---|---|
| 1 | **カード決済の審査申請** | D-75日 | 運営 | 加盟店審査は通常5営業日〜3週間。特定商取引法表記・返金規定・事業実態資料を先に用意 |
| 2 | **口座振替の審査申請** | D-75日（1と同時） | 運営 | ここが最長。審査2〜4週間＋口座登録のリードタイムが別途。**先に振替日を決める**（27日型が定番） |
| 3 | 審査通過・振替日／締切の確定 | D-45日 | 運営 | 新旧両社の**年間スケジュール表を入手**し、表1のうち自校の行を確定 |
| 4 | **保護者へ連絡（1回目：予告）** | D-45日 | 運営 | 「いつから」「引落日が変わるか」「明細の表示名が変わる」「◯月は旧、◯月から新」を明記。Web口振の登録依頼もここで送る |
| 5 | 口座振替の登録回収（Web口振 / 依頼書） | D-30日 | 運営 | **未登録者リストを毎週更新**。初回引落に間に合わない家庭は当月のみ振込 or カードで回収 |
| 6 | **旧システムの引き落としを止める** | 表1の締切より**さらに前**（下記3参照） | 運営 | 旧SaaSの請求確定日と収納代行の締切の**早いほう**が期限。停止した証跡（画面・メール）を残す |
| 7 | 旧システムの解約通知 | 解約希望日の**60日前**（契約書要確認） | 運営 | 6と別。データエクスポート（生徒・保護者・入金履歴）を**解約前に必ず取得** |
| 8 | **コーチの登録** | D-30日 | 運営 | 権限ロール（管理者／コーチ／閲覧）を先に設計。ログイン確認まで |
| 9 | **クラスの登録** | D-25日 | 運営 | 曜日・時間・定員・料金プラン。**料金プランのIDが請求のキー**になるので命名規則を固定 |
| 10 | **生徒名簿の移行** | D-20日 | 運営 | 旧CSV → 新システム。氏名・生年月日・在籍クラス・料金・兄弟割・休会者を移す。**休会/退会者を混ぜない** |
| 11 | 請求データの照合（最重要） | D-15日 | 運営＋経理 | 旧最終月の請求額と新初回の請求額を**1人ずつ突き合わせ**。差分ゼロを確認 |
| 12 | 新システムへ初回請求データ提出 | 表1の締切（D-6〜14営業日） | 運営 | **締切前日までに提出**。当日提出は事故になる |
| 13 | **保護者へ連絡（2回目：直前）** | D-7日 | 運営 | 「◯月◯日に◯◯（表示名）から引落」「残高確認のお願い」。表示名の周知漏れが問い合わせの最大要因 |
| 14 | **引き落とし開始** | D | 運営 | — |
| 15 | 結果確認・振替不能者のリカバリ | D+3〜6営業日 | 運営 | 不能者へ再請求。旧側の二重引落がないかも同時に確認 |

### 順番についてのコメント
提示された順番はほぼこのままで問題ない。2点だけ入れ替え・並行化を推奨する。

- **「保護者へ連絡」は2回に分ける**（予告：D-45日 / 直前：D-7日）。1回だけだと口座振替の登録が初回引落に間に合わない。
- **「コーチ登録・クラス登録・名簿移行」は審査待ちの期間に並行してやる**。ここは審査と依存関係がないので、直列に並べると1ヶ月まるごと無駄になる。
- **「引落を止める」は保護者連絡より締切が先に来ることがある**。表1の締切を先に確定してから連絡文面のスケジュールを決める。

## 3. 「止める連絡」の期限の出し方

止める期限は、次の**いちばん早い日付**になる。

```
止める期限 = min(
    旧・収納代行会社の請求データ提出締切,     ← 引落日の 6〜14営業日前 正午
    旧・管理システム(SaaS)の請求確定日,       ← 引落日の 20〜30日前が多い
    旧・管理システムの解約通知期限            ← 30〜60日前・書面
)  −  3営業日（安全マージン）
```

### 具体例：新システムの初回引落を 2026-11-27（金）にする場合

| 項目 | 日付 | 備考 |
|---|---|---|
| 旧側の最終引落（10月分） | 2026-10-27（火） | ここまでは旧で回す |
| **旧側 11月分の請求データ締切（6営業日前）** | **2026-11-18（水）正午** | この時点で未提出なら11月は旧で引落されない |
| 旧側が14営業日前締切の会社の場合 | 2026-11-06（金）正午 | 会社によってはここまで |
| **旧SaaSの請求確定（引落日の30日前想定）** | **2026-10-28（水）** | 実質これが本当の期限 |
| **旧側に「止めて」と連絡する日** | **2026-10-23（金）まで** | 上記から3営業日の安全マージン |
| 新側 初回請求データ提出締切（6営業日前） | 2026-11-18（水）正午 | 提出は 11-16（月）までに完了させる |
| 新側 初回引落 | 2026-11-27（金） | |
| 結果返却 / 入金 | 12-02（水）ごろ / 12-07（月）ごろ | 振替日+3 / +6営業日 |

### 参考：他の引落日パターン（2026年）

| 引落日 | 6営業日前 | 10営業日前 | 14営業日前 |
|---|---|---|---|
| 2026-10-27（火） | 10-19（月） | 10-13（火） | 10-06（火） |
| 2026-11-20（金） | 11-12（木） | 11-06（金） | 10-30（金） |
| 2026-11-26（木） | 11-17（火） | 11-11（水） | 11-05（木） |
| 2026-11-27（金） | 11-18（水） | 11-12（木） | 11-06（金） |
| 2026-12-04（金） | 11-26（木） | 11-19（木） | 11-13（金） |
| 2026-12-27（日）→ **12-28（月）繰越** | 12-18（金） | 12-14（月） | 12-08（火） |

※ 2026年の祝日（10-12 スポーツの日、11-03 文化の日、11-23 勤労感謝の日）を反映済み。

## 4. 事故防止チェックリスト

- [ ] 新旧両社の**年間スケジュール表（振替日ごとのデータ伝送期限）**を紙で入手した
- [ ] 旧側の停止を、**画面キャプチャ＋メール**の両方で証跡化した
- [ ] 移行月の請求額を、旧最終月と**1人ずつ突き合わせ**た（兄弟割・休会・途中入会を含む）
- [ ] 休会者・退会者を新システムに**請求対象として持ち込んでいない**
- [ ] 口座振替の登録が間に合わない家庭の**当月の回収方法**を決めた
- [ ] 保護者向けに**通帳の表示名（摘要）が変わること**を告知した
- [ ] 二重引落が起きた場合の**返金フロー（誰が・いつ・どう返すか）**を先に決めた
- [ ] 旧システムのデータを**解約前にエクスポート**した（生徒・保護者・入金履歴・振替不能履歴）
- [ ] 初回引落日の直後に、**結果確認とリカバリの担当と時間**を押さえた
